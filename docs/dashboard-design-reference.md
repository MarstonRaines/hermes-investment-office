## 1. 产品定位（用户画像，来自三轮 QA）

| 维度 | 结论 |
|---|---|
| 使用时刻 | **早上看日报时**为主；盘中/晚上为辅 |
| 核心目的 | 观察池所有标的的**行情、K线、当日估值、投资观点状态、事件** + "有无变动需要处理" |
| 看 vs 问 | **能看的就看**（dashboard 展示优先，对话做深入分析与决策） |
| 设备 | **Mac 大屏为主**（信息密度可高） |
| 持仓 | 有真实持仓要展示 |
| 心智模型 | **两分法：观察池标的（研究视角）vs 持仓标的（组合视角）**，重叠但视角不同 |

核心原则（从问答提炼）：

> **Dashboard = 观察池与持仓的每日状态墙。列表紧凑、详情完整、变动显眼。所有估值、投资观点与事件状态一眼可见，具体分析交给对话。**

## 2. 信息架构总览

```text
┌─────────────────────────────────────────────────┐
│  Hermes Investment Office  Dashboard           │
│  [今日] [标的] [组合] [问 Hermes]               │
├─────────────────────────────────────────────────┤
│                                                 │
│  今日页    ← 数据状态 + 需处理事项 + 日报 + 组合摘要 │
│  标的页    ← 观察池/全部标的筛选 → 同一详情与初始化  │
│  组合页    ← 手工账本/净值/风险/建议               │
│  问 Hermes ← 持久聊天 + 历史管理 + 确认写入研究档案 │
│                                                 │
│  标的详情页                                      │
│    日K+MA / 客观与主观估值 / ETF 指标 /           │
│    研究观点 / 事件时间线 / 来源 / 局部历史模式      │
└─────────────────────────────────────────────────┘
```

### 与冻结规范 §40.1 历史板块的映射

下表只解释旧规范板块如何落入当前四入口，不表示旧板块名称仍是一级导航。

| 冻结规范板块 | 新架构落位 | 说明 |
|---|---|---|
| TODAY（Needs Attention / Daily Brief）| **今日页** | 合并（用户决策：先合并后分）|
| PORTFOLIO（Value/Cash/Allocation/Risk/Target Weight）| **组合页** | Target Weight 对比后置（用户未选）|
| RESEARCH（Watchlist / Latest Research）| **标的页 + 事件时间线 + Hermes 历史** | 研究围绕标的聚合 |
| THESIS（Healthy/Warning/Broken/Due for Review）| 标的详情页 + 今日页聚合 | 状态灯语义（见 §6）|

## 3. 今日页（TODAY）

**打开即见。目标：30 秒内回答"今天有什么需要我处理的？"**

```text
今日页
├── 数据新鲜度状态栏
│     └── OK / WARNING / STALE / FAILED + 受影响数据域
├── 需处理事项（按严重度排序）
│     ├── 🔴 红线触发 / 投资观点失效          （红色）
│     ├── 🟠 假设转 WARNING / 估值带进极端区    （橙色）
│     └── 🟡 财报发布 / 价格异动 / 到期复核     （黄色）
├── 每日简报（最新一期；原文折叠）
├── 组合指标与净值 / 配置 / 风险概览
└── 观察池行情表
```

- 需处理事项的**判定走系统自动规则**（attention_rules.yaml 确定性触发，LLM 只解释），用户后续可调阈值（"先自动后调"）；
- 日报与今日页保持合并；历史研究通过标的事件、局部历史模式和 Hermes 历史会话查看。

## 4. 标的页（Instrument Center）

**核心页。目标：一屏扫完所有关注标的的状态。**

### 4.1 已实现列表（紧凑）

```text
桌面：代码 / 名称 / 最新价 / 日涨跌 / 跟踪指数 / 行情日
窄屏：代码 / 名称 / 最新价 / 日涨跌
```

- 桌面表格展示六列真实行情；`≤760px` 隐藏“跟踪指数、行情日”，固定保留四个核心列，不通过缩小字体挤入更多字段。
- 估值、研究状态、事件与来源在下方同一标的详情中查看，不在移动列表重复堆叠。
- 操作：通过“查看标的详情”选择器打开详情；“添加或管理标的”只保留“添加新标的 / 移出观察池”两条路径。
- 新增：用户只输入六位代码和名称；Backend 自动推断市场、A 股/ETF 类型、交易所与 Provider Symbol，加入后立即同步近一年行情。
- 空状态：观察池为空 → 引导打开“管理观察池”并输入代码和名称。

### 4.2 写入与移动行为

- 加入标的先显示代码、名称和初始化影响预览，再由“确认加入并初始化”写入；移出观察池也必须先预览并确认，且不删除标的研究档案。
- 页面默认查看最新范围；局部历史模式只存在于具体标的详情，进入后禁止补齐资料、估值和任何研究写入。
- 移动端导航入口明确显示“导航”，可恢复抽屉；可见文字字号下限为 `12px`。

## 5. 组合页（Portfolio）

**组合视角。目标：组合整体状态 + 每只持仓的贡献。**

```text
组合页
├── 总览卡
│     └── 组合净值 / 现金 / 证券市值 / 未实现盈亏
├── 当前持仓
│     └── 代码 / 名称 / 数量 / 平均成本 / 最新价 / 市值 / 未实现盈亏 + 净值历史
├── 手工记账
│     └── 迁入现有持仓 / 现金变动 / 买卖、分红、费用 / REVERSAL 更正
├── 流水
│     └── 仅追加交易记录与更正关系
└── 交易建议
      └── 人工批准或拒绝；批准后另行登记外部实际成交
```

- 组合是用户手工维护的本地 REAL 账本，不是券商账户；系统不连接券商、不导入券商持仓、不下单或划转资金。
- 迁入、现金、交易、REVERSAL、建议状态与实际成交登记全部先预览，再独立确认；历史模式严格只读。
- 组合数字全部来自 Backend，**Dashboard 自身零业务计算**（冻结规范 §40）。今日页另行展示 Backend 返回的净值、配置与风险概览。

## 6. 标的详情页（共用）

```text
标的详情页
├── 头部：名称 / 代码 / 价格 / 涨跌 / 当日估值快照（含数据新鲜度）
├── 标签页
│    ├── 总览    四项关键指标 + 日 K + 最新财务事实
│    ├── 行情    不复权日 K + MA5 / MA20 / MA30 + 原始历史表
│    ├── 估值 / ETF 指标
│    │           个股：Backend 客观指标 + 用户确认的 Bear/Base/Bull 情景
│    │           ETF：指标日期 / 指数 PE / 指数 PB / 额度与质量状态
│    ├── 研究    投资观点状态、健康度、版本与正文
│    ├── 事件    披露 / 公司行动 / 笔记 / 证据 / 投资观点 / 复核时间线
│    └── 来源    数据域 / Provider / provenance / as_of / quality
```

- 详情页默认用于阅读；行情、客观估值、研究、事件与来源不在前端重算。主观估值允许在详情页录入，但必须先展示情景、概率与依据的预览，再由用户显式确认；建立或修订长期投资观点仍优先引导到 Hermes 对话并确认落库。
- K 线数据：`get_price_history`（as_of PIT），默认近一年、不复权；MA5/MA20/MA30 随 Backend 行情历史返回，Dashboard 不重算。日 K 使用 A 股红涨绿跌；MA5/MA20/MA30 分别为蓝、琥珀、紫。
- 每个标的、标签页的行情图必须使用独立组件身份，切换标的时不得保留上一标的的图形数据。
- 涨跌、收益和盈亏采用 A 股“红涨绿跌”；系统健康仍为绿、系统失败仍为红，两类语义不得混用。

## 7. 问 Hermes

**目标：不离开投资工作台，直接深入研究任何标的。**

```text
问 Hermes
├── 本机连接状态（版本 / 会话保存 / 明确故障）
├── 历史会话管理（列表 / 恢复 / Markdown 导出 / 二次确认删除）
├── 持久对话历史（用户 / Hermes 正文；推理过程不展示）
├── 问题建议（持仓 / 观察池 / 系统外股票）
└── 输入框（股票代码、名称或自然语言研究问题）
```

- 系统内标的：Hermes 通过 Backend MCP 获取事实、确定性计算、数据新鲜度和 provenance。
- 系统外标的：Hermes 使用公开披露与可靠网络来源，明确来源和时点；不得伪装成 Backend 事实或自行计算关键指标。
- 页面通过本机 `127.0.0.1:9119` Hermes WebSocket 网关流式接收回答；历史管理调用同一 Hermes 服务的带令牌本机 Session API。会话由 Hermes 持久化，Dashboard 不保存模型状态，也不直接访问 `state.db`。
- 页面不提供券商、下单、REAL 流水写入或建议审批能力。

```text
标的详情
├── 局部历史模式（指定日期、严格只读）

```

## 9. 状态灯语义（视觉语言）

| 灯 | 含义 | 判定来源 |
|---|---|---|
| ● 绿 | 投资观点健康（全部假设 `HEALTHY`）| ThesisService |
| ● 黄 | 存在 `WARNING` 假设 / 估值进入极端区 / 事件待处理 | Thesis + 引擎 |
| ● 红 | 假设 `BROKEN` / 红线触发 / 投资观点 `INVALIDATED` | ThesisService |
| ○ 灰 | 无投资观点（纯观察）| — |

事件标记：`●` 数量 = 未读事件（财报/公告/异动），点开进入详情事件页。

无障碍与对比度基线：四项主导航的可访问名称只包含中文标签，线性 SVG 图标仅作装饰；可见文字字号下限为 `12px`。亮色主题的小字号蓝/绿/红/琥珀文字分别使用 `#075fcc`、`#067647`、`#b42318`、`#854d0e`，对白底对比度均不低于 5.69:1。主按钮白字对操作蓝达到 5.97:1；暗色主题由系统偏好切换对应 token。

## 10. 数据契约映射（视图 → API）

| 视图 | 数据 | API（ts07 REST 等价）|
|---|---|---|
| 今日页 日报 | daily_briefs 最新 | `get_daily_context` / `save_daily_brief`（读）|
| 今日页 需处理 | attention_items | daily_context.attention_items |
| 今日页 数据状态 | freshness | daily_context.data_freshness |
| 标的 列表 | watchlist 或全部 Instrument + 每标的行情 | `get_watchlist`（ADR-006）+ `list_instruments` |
| 详情 行情 | K线 | `get_price_history` |
| 详情 估值 | 估值历史 | `get_valuation_history` / `get_etf_metrics` |
| 详情 观点 | Thesis | `get_thesis`（含 evidence/reviews）|
| 持仓 总览 | 净值/收益 | `get_portfolio` / `get_positions` |
| 持仓 风险 | 暴露/集中度/回撤 | `get_portfolio_exposure` / `get_portfolio_risk` |
| 标的/组合历史 | PIT 历史 | `office/instruments/{id}?as_of=` / `office/portfolios?as_of=` |
| 问 Hermes | 持久研究会话 | Hermes `session.create` / `session.resume` / `session.close` / `prompt.submit`；本机 Session API 负责列表、消息导出与删除；系统内事实继续走 MCP |

**架构约束**：所有业务视图只经 Backend REST；“问 Hermes”只经本机 Hermes 会话网关。两者都无 SQLAlchemy 依赖、无业务计算（ARCH-DSH-001~004 与 ADR-010 守卫测试覆盖）。

### 结构化来源与来源页

- TuShare：A 股/场内 ETF 行情、复权、财务、基金 NAV 与 A 股指数数据主链路。
- AkShare 新浪源：A 股行情 fallback 与交易日历；东方财富源：ETF 行情/NAV、持仓与额度状态；同花顺源：财务摘要 fallback。
- Yahoo Finance：美国指数与 USD/CNY；FRED：宏观序列与汇率交叉验证；乐咕乐股：A 股指数估值历史。
- 新浪交易日历同步到本地持久表并可人工校准。标的详情“来源”页按真实响应展示数据域、Provider、`provenance_id`、时点/报告期和质量状态；没有记录时显示真实空状态。

## 13. 已收口问题

1. v0.1 使用一个默认观察池，多池界面后置。
2. v0.1 不建立独立未读系统；事件按时间排序并保留来源。
