# Dashboard 信息架构设计参考（dashboard-design-reference）

> 状态：**DRAFT v0.1（2026-08-23，用户 QA 三轮定稿）**
>
> 定位：M7 Dashboard 与未来 macOS .app（ADR-004 D4）的**共用信息架构输入**；视觉/组件级设计待施工时细化
>
> 约束：冻结规范 §40（只读 Backend API、薄展示层、绑定 127.0.0.1）、ADR-004（.app 演进预留）、ADR-006（观察池领域对象）

---

## 1. 产品定位（用户画像，来自三轮 QA）

| 维度 | 结论 |
|---|---|
| 使用时刻 | **早上看日报时**为主；盘中/晚上为辅 |
| 核心目的 | 观察池所有标的的**行情、K线、当日估值、Thesis 状态、事件** + "有无变动需要处理" |
| 看 vs 问 | **能看的就看**（dashboard 展示优先，对话做深入分析与决策） |
| 设备 | **Mac 大屏为主**（信息密度可高） |
| 持仓 | 有真实持仓要展示 |
| 心智模型 | **两分法：观察池标的（研究视角）vs 持仓标的（组合视角）**，重叠但视角不同 |

核心原则（从问答提炼）：

> **Dashboard = 观察池与持仓的每日状态墙。列表紧凑、详情完整、变动显眼。所有估值/Thesis/事件状态一眼可见，具体分析交给对话。**

## 2. 信息架构总览

```text
┌─────────────────────────────────────────────────┐
│  Hermes Investment Office  Dashboard           │
│  [今日] [观察池] [持仓] [回顾]                   │
├─────────────────────────────────────────────────┤
│                                                 │
│  今日页    ← 日报 + 需处理事项聚合（打开即见）      │
│  观察池页  ← 所有关注标的列表行 → 标的详情页（共用） │
│  持仓页    ← 组合净值/明细/风险 → 标的详情页（共用） │
│  回顾页    ← 历史日报 / Thesis 演变 / 研究笔记     │
│                                                 │
│  标的详情页（观察池/持仓共用，数据同源）            │
│    K线 / 估值带+合理区间 / 折溢价(ETF) /          │
│    Thesis 状态 / 事件时间线 / 组合关系             │
└─────────────────────────────────────────────────┘
```

### 与冻结规范 §40.1 的映射

| 冻结规范板块 | 新架构落位 | 说明 |
|---|---|---|
| TODAY（Needs Attention / Daily Brief）| **今日页** | 合并（用户决策：先合并后分）|
| PORTFOLIO（Value/Cash/Allocation/Risk/Target Weight）| **持仓页** | Target Weight 对比后置（用户未选）|
| RESEARCH（Watchlist / Latest Research）| **观察池页 + 回顾页** | Watchlist 列表行为核心 |
| THESIS（Healthy/Warning/Broken/Due for Review）| 标的详情页 + 今日页聚合 | 状态灯语义（见 §6）|

## 3. 今日页（TODAY）

**打开即见。目标：30 秒内回答"今天有什么需要我处理的？"**

```text
今日页
├── 日报区（Daily Brief，最新一期）
│     └── 结构化呈现：Attention 项解释 + 组合摘要 + 观察池摘要
├── 需处理事项（Actionable Items，按严重度排序）
│     ├── 🔴 红线触发 / Thesis BROKEN        （红色）
│     ├── 🟠 假设转 WARNING / 估值带进极端区    （橙色）
│     └── 🟡 财报发布 / 价格异动 / 到期复核     （黄色）
└── 数据状态栏（freshness）
      └── OK / WARNING / STALE / FAILED + 各数据源状态（非 OK 时置顶警示）
```

- 需处理事项的**判定走系统自动规则**（attention_rules.yaml 确定性触发，LLM 只解释），用户后续可调阈值（"先自动后调"）；
- 日报与今日页**先合并，用起来再拆**独立历史页（回顾页承载历史）。

## 4. 观察池页（Watchlist）

**核心页。目标：一屏扫完所有关注标的的状态。**

### 4.1 列表行（紧凑）

```text
┌──────────────────────────────────────────────────────────┐
│ 名称       价格     涨跌%    估值状态      状态灯  事件    │
│ 贵州茅台  1413.2   +1.24%   FAIR·区间中    ●绿     ●      │
│ 纳指ETF   1.382    -0.86%   折价-12%      ●黄     ●●     │
│ 沪深300ETF 4.118   +0.31%   CHEAP·区间下沿 ●绿     —      │
│ 海天味业   41.52   -2.10%   EXPENSIVE    ●红     ●      │
└──────────────────────────────────────────────────────────┘
```

- 列：名称 / 价格 / 当日涨跌 / **估值状态**（个股：估值带+合理区间位置；ETF：折溢价）/ **状态灯**（Thesis 健康度聚合）/ 事件标记（未读事件数）
- 排序：默认按"需处理优先级"（事件/状态灯异常置顶），可切换按估值/涨跌排序
- 操作：点行 → 标的详情页；行尾按钮 → 移出观察池（RESEARCH_WRITE）
- 空状态：观察池为空 → 引导添加（"对话中告诉 Hermes '把 XX 加入观察池'"）

### 4.2 估值状态列语义

| 类型 | 展示 | 数据源 |
|---|---|---|
| 个股 | 估值带（VERY_CHEAP~VERY_EXPENSIVE）+ 合理估值区间（Bear/Base/Bull）位置：如 `FAIR·现价≈Base` | ETF Engine 日算 → `get_latest_valuation` |
| ETF | 折溢价率：如 `折价-12%`（QDII）/ 指数估值带（宽基）| `get_etf_metrics` |
| 基础 | PE/PB 及历史分位作为估值带构成的子信息（tooltip/展开）| 引擎输出 |

## 5. 持仓页（Portfolio）

**组合视角。目标：组合整体状态 + 每只持仓的贡献。**

```text
持仓页
├── 总览卡
│     ├── 总资产(CNY) / 现金 / 当日变动 / 累计收益（TWR）
│     └── 净值曲线（历史 PortfolioSnapshot 序列，时间范围可切）
├── 持仓明细（列表行）
│     ├── 名称 / 数量 / 成本 / 现价 / 市值 / 盈亏(额+%) / 仓位%
│     └── 行 → 标的详情页（共用）
├── 风险与暴露
│     ├── 行业暴露 / 资产类暴露（含 ETF 穿透后真实暴露）
│     ├── 集中度（最大持仓占比 / 单标的暴露）
│     └── 回撤指标（组合/持仓）
└── （后置）目标配置 vs 实际配置对比
```

- 持仓与观察池**共用标的详情页**（数据同源）；
- 组合数字全部来自 Backend（`get_portfolio` / `get_positions` / `get_portfolio_exposure` / `get_portfolio_risk`），**dashboard 自身零计算**（冻结规范 §40）。

## 6. 标的详情页（共用）

```text
标的详情页
├── 头部：名称 / 代码 / 价格 / 涨跌 / 当日估值快照（含 freshness）
├── 标签页
│    ├── 行情    K线（日/周/月，复权口径标注）+ 成交量 + 关键价格位
│    ├── 估值    估值带五档图 / Bear-Base-Bull 区间 vs 现价 / 安全边际 /
│    │            PE-PB 历史分位 / 估值历史序列（valuation_runs）
│    │           （ETF：折溢价历史 / NAV vs 市价 / 指数 PE 分位 / 汇率贡献）
│    ├── 观点    Thesis 状态（lifecycle + health 状态灯）、假设清单
│    │            （statement/status/test_condition）、红线、复核历史、
│    │            卖出条件 —— 用通俗语言呈现（"观点/假设"而非"thesis"术语）
│    ├── 事件    时间线：财报 / 公告 / 价格异动 / Thesis 事件 / 公司行为
│    └── 关系    组合持仓（若有）：成本/盈亏/暴露贡献；观察池状态
```

- 详情页是**只读**的；所有交互动作（加假设、调整估值参数、建 Thesis）引导到对话（"告诉 Hermes：把 XX 的 WACC 改成 9%"）；
- K 线数据：`get_price_history`（as_of PIT）；估值：`get_valuation_history` / `get_etf_metrics`。

## 7. 回顾页（Review）

```text
回顾页
├── 日报历史（按日期，可回看任意一日）
├── Thesis 演变（每个 Thesis 的版本链：v1→v2→v3 + 变更原因）
│     —— 回答"我的观点是怎么演变的"
└── 研究笔记（research_notes 列表）
```

## 8. 状态灯语义（视觉语言）

| 灯 | 含义 | 判定来源 |
|---|---|---|
| ● 绿 | Thesis 健康（全部假设 HEALTHY）| ThesisService |
| ● 黄 | 存在 WARNING 假设 / 估值进入极端区 / 事件待处理 | Thesis + 引擎 |
| ● 红 | 假设 BROKEN / 红线触发 / Thesis INVALIDATED | ThesisService |
| ○ 灰 | 无 Thesis（纯观察）| — |

事件标记：`●` 数量 = 未读事件（财报/公告/异动），点开进入详情事件页。

## 9. 数据契约映射（视图 → API）

| 视图 | 数据 | API（ts07 REST 等价）|
|---|---|---|
| 今日页 日报 | daily_briefs 最新 | `get_daily_context` / `save_daily_brief`（读）|
| 今日页 需处理 | attention_items | daily_context.attention_items |
| 今日页 数据状态 | freshness | daily_context.data_freshness |
| 观察池 列表 | watchlist + 每标的行情/估值/状态 | `get_watchlist`（ADR-006）+ `get_market_snapshot` + `get_latest_valuation` + `get_etf_metrics` + `get_thesis` |
| 详情 行情 | K线 | `get_price_history` |
| 详情 估值 | 估值历史 | `get_valuation_history` / `get_etf_metrics` |
| 详情 观点 | Thesis | `get_thesis`（含 evidence/reviews）|
| 持仓 总览 | 净值/收益 | `get_portfolio` / `get_positions` |
| 持仓 风险 | 暴露/集中度/回撤 | `get_portfolio_exposure` / `get_portfolio_risk` |
| 回顾 | 历史 | `get_daily_context`(历史) / `get_thesis`(版本) / `search_research` |

**架构约束**：所有视图只经上述 API；无 SQLAlchemy 依赖、无业务计算（ARCH-DSH-001~004 测试覆盖）。
