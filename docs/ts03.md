## 1. 执行摘要

本报告把 **TS-02 PostgreSQL ERD（40 张表 / 9 个表族）** 翻译为两层可执行契约：

1. **SQLAlchemy 2.0 ORM 层**（`backend/app/<module>/models.py`）——PostgreSQL 物理 Schema 的 Python 表达，逐表给出 `Mapped[]` 风格声明、关系与约束；
2. **Pydantic v2 域模型层**（`backend/app/<module>/schemas.py`）——API / MCP 边界的入参与出参、跨字段校验规则、序列化契约，以及 MCP 统一响应包络 `ResponseEnvelope`。

两者分工是本阶段最需要冻结的一句话：

> **ORM 负责持久化与数据库约束（表、列、CHECK、唯一约束、索引、触发器）；Pydantic 负责 API / 校验 / 边界（字段校验、跨字段规则、序列化、MCP 包络）。两者通过 `ConfigDict(from_attributes=True)` 单向桥接（ORM 实例 → Read Schema），Schema 绝不反向产生 ORM 状态。**

### 1.1 关键设计结论

| # | 结论 | 落点 |
|---|---|---|
| 1 | 枚举以 `StrEnum` 单点定义于 `common/enums.py`，ORM 与 Pydantic 共用同一份；DB 存 `TEXT + 显式命名 CHECK`（不用 PG enum type），Pydantic 用枚举类型直接校验 | §3 / §4.3 |
| 2 | 每张表恰属于一个领域模块（`TABLE_OWNER` 白名单，架构测试可机器检查）；跨模块只允许单向 FK 引用，ORM `relationship` 只在模块内声明，聚合视图由服务层组装 | §6 |
| 3 | 5 张核心表（`provenance_records`、`financial_facts`、`thesis_revisions`、`portfolio_transactions`、`valuation_runs`）在 ORM 层用注释固化 ts01/ts02 业务不变量（append-only、PIT、乐观并发、金额符号约定），其余 35 张紧凑但完整可编译 | §5 |
| 4 | ts01/ts02 的全部校验规则在 Pydantic 层变成类型系统可执行的约束：`quality_score ∈ [0,1]`、`base_currency='CNY'`、`is_qdii ⇒ underlying_index_id`、`AT_RISK` 天然被拒、premium 日期对齐 | §8 |
| 5 | 不可变表只暴露 `create` 接口形态（仓储层无 `update/delete` 方法），可变表用乐观并发（thesis head / instrument.version），状态迁移用条件 UPDATE | §10 |

## 2. 技术选型与约定（TS-03.1）

### 2.1 技术栈（冻结）

```text
Python 3.12
SQLAlchemy 2.0（Declarative + Mapped[] 风格，废弃 legacy Column 直写）
Alembic 1.13+（autogenerate + 手工触发器）
Pydantic v2（model_config / model_validator / field_validator / ConfigDict）
psycopg v3 驱动
PostgreSQL 16+
```

冻结规范 §7 的"模块化单体 + 不引入 MQ/微服务"约束在此不变；本层只定义"如何把 ts02 的 DDL 变成 Python"。

### 2.2 声明式风格：Mapped[] + mapped_column

SQLAlchemy 2.0 统一类型注解风格：

```python
instrument_id: Mapped[UUID] = UUIDPrimaryKeyMixin.pk("instrument_id")
name: Mapped[str] = mapped_column(Text, nullable=False)
nav: Mapped[Decimal] = mapped_column(PRICE, nullable=False)
```


- 列名一律来自 ts02，禁止自行改名；
- 可空性用 `Mapped[T | None]` 表达，`nullable` 与注解保持一致；
- 所有约束 / 索引显式命名，名称与 ts02 §1.3、§11 清单一致；
- **枚举列注解为枚举类型仅为静态类型提示**：DB 列是 `TEXT`，ORM 读取返回 `str`，域层用 `Enum(value)` 转换，Pydantic 在边界自动完成（见 §3 注）。

### 2.3 类型与精度规范（全库统一，直接继承 ts02 §1.2）

| 用途 | SQLAlchemy 类型常量 | ts02 物理类型 |
|---|---|---|
| 主键 / 外键 | `PgUUID(as_uuid=True)` | UUID |
| 时间点 | `TIMESTAMPTZ` | TIMESTAMPTZ |
| 业务日期 | `DATE` | DATE |
| 金额（CNY） | `MONEY = Numeric(18, 4)` | NUMERIC(18,4) |
| NAV / 单价 / 指数点位 | `PRICE = Numeric(12, 6)` | NUMERIC(12,6) |
| 数量 / 份额 | `QTY = Numeric(24, 6)` | NUMERIC(24,6) |
| 比率（0-1） | `RATIO = Numeric(10, 6)` | NUMERIC(10,6) |
| 质量评分 | `QUALITY = Numeric(5, 4)` | NUMERIC(5,4) |
| 汇率 / 假设值 / 复权因子 | `FX_RATE = Numeric(16, 8)` | NUMERIC(16,8) |
| 指数 PE / PB | `PE_PB = Numeric(12, 4)` | NUMERIC(12,4) |
| 财务事实值 | `FACT = Numeric(24, 6)` | NUMERIC(24,6) |
| 一手股数 | `LOT = Numeric(12, 0)` | NUMERIC(12,0) |

> 定点语义是"黄金值测试可复现"的前提（ts02 §1.2）：**全库禁止 float 列**；Python 侧金额一律 `Decimal`。

### 2.4 枚举：TEXT + CHECK（不使用 PG enum type）

ts02 §1.2 冻结：不使用 PostgreSQL `CREATE TYPE`。理由：Alembic 对 CHECK 约束的演进（加值 = 改 CHECK 文本）比 PG enum（加值 = `ALTER TYPE ADD VALUE`，且受已用值约束）安全；TEXT + 显式命名 CHECK 与迁移工具链配合最好。

```python
status: Mapped[ThesisLifecycleStatus] = mapped_column(Text, nullable=False)
```


CHECK 由 `enum_ck()` 从枚举值自动生成（§4.3）——**枚举定义是唯一事实来源**，枚举加值 ⇒ 新 migration 自动同步 CHECK。

### 2.5 JSONB 使用边界

JSONB 只用于"结构化、但无查询 / 约束需求"的内容：

- 白名单：`thesis_body`、`result_json`、`holdings_json`、`exposures`、`risk_summary`、`data_freshness`、`markets`、`engine_versions`、`source_status`、`sections`、`detail`、`payload`、`params`、`quality_flags`、`source_tags`、`event_data`、`artifact_ref`、`parameters`；
- **禁止**把需要关系语义的数据塞进 JSONB（ts01：Evidence 必须走 `evidence_links` 桥接表，不用 `evidence_json`；thesis 假设必须落 `thesis_assumptions` 行）；
- JSONB 键必须是字符串（Postgres JSON 约束）；内嵌 Decimal 写库前必须显式转 str / float（陷阱见 §9.4）。

### 2.6 时区与业务日（冻结）

- 全部时间戳列 `TIMESTAMPTZ`，应用层统一 **UTC 存储、Asia/Shanghai 展示**（冻结规范 §14.2）；
- 业务日（`trade_date` / `market_date` / `nav_date` / `period_end` / `snapshot_date`…）单独 `DATE` 列，绝不与时间戳混用（ts02 §1.1）；
- QDII 时序（`market_date` / `nav_date` / `underlying_session_date` / `fx_as_of`）四个时点必须同时建模（ts01 冻结，见 §5.2 `ETFMetricSnapshot`）。

### 2.7 命名规范（继承 ts02 §1.3）

```text
表名：snake_case 复数（instruments, portfolio_transactions）
主键：<单数实体>_id（instrument_id, provenance_id）
外键：<引用表单数>_id（portfolio_id, thesis_id）
布尔：is_ 前缀（is_qdii, is_restated, is_red_line）
时间：created_at / updated_at / published_at / retrieved_at / observed_at / as_of / started_at / finished_at
CHECK：ck_<表>_<列>_check（枚举）/ ck_<表>_<列>_range（数值区间）/ 语义名（如 ck_portfolios_base_currency_cny）
索引：ix_<表>_<列>；唯一：uq_<表>_<列>；部分索引：ix_<表>_<列>_lookup
```

## 4. 基础设施（TS-03.3）

### 4.1 Base 与命名约定

```python
# backend/app/common/base.py
from sqlalchemy import MetaData
from sqlalchemy.orm import DeclarativeBase

# 显式命名约定：让 Alembic autogenerate 生成的约束/索引名可预测、可幂等。
# 本报告所有约束均显式命名（见各表 __table_args__），约定只作为"漏网之鱼"的兜底，
# 保证任何未命名约束也能生成稳定名称。多列唯一约束必须显式命名
# （约定模板只用 column_0，会丢列）。
NAMING_CONVENTION = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}


class Base(DeclarativeBase):
    metadata = MetaData(naming_convention=NAMING_CONVENTION)
```


### 4.2 主键 / 时间戳 mixin

```python
# backend/app/common/mixins.py
from datetime import datetime
from uuid import UUID, uuid4

from sqlalchemy import func
from sqlalchemy.dialects.postgresql import UUID as PgUUID
from sqlalchemy.orm import Mapped, mapped_column
from app.common.types import TIMESTAMPTZ


class UUIDPrimaryKeyMixin:
    """UUID 主键约定（ts02 §1.2：全表 UUID PRIMARY KEY）。

    ts02 要求主键列名 = <单数实体>_id（instrument_id / provenance_id / …），
    普通 mixin 属性无法为每张表生成不同列名，故本 mixin 只固化两个不变量：
      1) 类型 = UUID（as_uuid=True，Python 侧 UUID 对象）；
      2) 默认值 = uuid4()（与 gen_random_uuid() 等价的客户端生成，利于批量插入）。
    列名由每个模型按 ts02 显式声明。架构测试校验：每表恰好一个 UUID 主键，
    禁止业务键（symbol / 日期复合键）作主键。
    """

    @staticmethod
    def pk(name: str) -> Mapped[UUID]:
        """生成 ts02 命名风格的 UUID 主键列（运行时即列对象，注解仅供静态类型提示）。"""
        return mapped_column(name, PgUUID(as_uuid=True), primary_key=True, default=uuid4)


class CreatedAtMixin:
    """append-only 表统一 created_at（DB 默认 now()）。"""
    created_at: Mapped[datetime] = mapped_column(
        TIMESTAMPTZ, nullable=False, server_default=func.now())


class TimestampMixin(CreatedAtMixin):
    """可变表统一 created_at + updated_at（onupdate 由 ORM/服务层维护）。"""
    updated_at: Mapped[datetime] = mapped_column(
        TIMESTAMPTZ, nullable=False, server_default=func.now(), onupdate=func.now())
```

```python
# backend/app/common/db.py —— 约束助手
from enum import StrEnum
from sqlalchemy import CheckConstraint


def enum_ck(table: str, column: str, enum_cls: type[StrEnum]) -> CheckConstraint:
    """生成 ts02 §1.3 命名规范的枚举 CHECK：ck_<表>_<列>_check。

    枚举定义是唯一事实来源：加值/删值后由 Alembic 生成新 migration 同步 CHECK。
    """
    values = ", ".join(f"'{m.value}'" for m in enum_cls)
    return CheckConstraint(f"{column} IN ({values})", name=f"ck_{table}_{column}_check")


def range_ck(table: str, column: str, low: str, high: str) -> CheckConstraint:
    """数值区间 CHECK（如 quality_score 0-1）：ck_<表>_<列>_range。"""
    return CheckConstraint(f"{column} >= {low} AND {column} <= {high}",
                           name=f"ck_{table}_{column}_range")
```

```python
class PortfolioTransaction(Base, CreatedAtMixin):
    """Transaction Ledger —— 组合唯一事实来源（append-only，核心表）。

    冻结约定（ts02 §7.3，与 TS-06 Portfolio Engine 对齐）：
      - amount_cny 现金视角：BUY 负 / SELL 正 / DIVIDEND 正 / FEE 负；
        数据层存"绝对值语义 + 公式负责符号"，禁止混用正负约定；
      - 纠错 = REVERSAL 新记录（reverses_transaction_id 指向原单），禁止 UPDATE；
      - ledger replay = fold(transactions ORDER BY trade_at, created_at)。
    """
    __tablename__ = "portfolio_transactions"
    __table_args__ = (
        CheckConstraint(
            "transaction_type IN ('CASH_IN','CASH_OUT') OR instrument_id IS NOT NULL",
            name="ck_transactions_instrument_required"),
        CheckConstraint(
            "reverses_transaction_id IS NULL OR reverses_transaction_id <> transaction_id",
            name="ck_transactions_reversal"),
        Index("ix_transactions_portfolio_date", "portfolio_id", "trade_date"),
        Index("ix_transactions_portfolio_instrument", "portfolio_id", "instrument_id"),
        enum_ck("portfolio_transactions", "transaction_type", TransactionType),
        enum_ck("portfolio_transactions", "source", TransactionSource),
    )
    transaction_id: Mapped[UUID] = pk("transaction_id")
    portfolio_id: Mapped[UUID] = mapped_column(ForeignKey("portfolios.portfolio_id"), nullable=False)
    account_id: Mapped[UUID | None] = mapped_column(ForeignKey("accounts.account_id"))
    instrument_id: Mapped[UUID | None] = mapped_column(ForeignKey("instruments.instrument_id"))  # CASH 类可空
    transaction_type: Mapped[TransactionType] = mapped_column(Text, nullable=False)
    quantity: Mapped[Decimal | None] = mapped_column(QTY)              # BUY/SELL/DIVIDEND
    price_cny: Mapped[Decimal | None] = mapped_column(MONEY)           # 成交单价
    amount_cny: Mapped[Decimal] = mapped_column(MONEY, nullable=False) # 成交金额（符号约定见类注释）
    fees_cny: Mapped[Decimal] = mapped_column(MONEY, nullable=False, server_default=text("0"))
    tax_cny: Mapped[Decimal] = mapped_column(MONEY, nullable=False, server_default=text("0"))
    trade_at: Mapped[datetime] = mapped_column(TIMESTAMPTZ, nullable=False)
    trade_date: Mapped[date] = mapped_column(Date, nullable=False)     # A 股交易日
    source: Mapped[TransactionSource] = mapped_column(Text, nullable=False)
    reverses_transaction_id: Mapped[UUID | None] = mapped_column(
        ForeignKey("portfolio_transactions.transaction_id"))           # 纠错引用
    note: Mapped[str | None] = mapped_column(Text)
    provenance_id: Mapped[UUID | None] = mapped_column(ForeignKey("provenance_records.provenance_id"))
    created_by: Mapped[str] = mapped_column(Text, nullable=False)
```

## 6. 模块归属与白名单（TS-03.5）

### 6.1 设计规则（冻结）

1. **每张表恰属于一个领域模块**：定义该表 ORM 类的 `models.py` 必须位于 `backend/app/<owner>/`，禁止跨模块定义表——这是架构测试"数据库访问边界"白名单的基础（冻结规范 §46.2）；
2. **跨模块只允许单向 FK 引用**：`etf_profiles.underlying_index_id → instruments`、`provenance_records.ingestion_run_id → jobs`、`trade_proposals.thesis_revision_id → thesis` 等合法；反向依赖（如 thesis → portfolio）由 import-linter 拦截；
3. **ORM `relationship` 只在模块内声明**：跨模块关联用"FK 列 + 服务层显式查询/组装"，避免惰性加载与隐式耦合（冻结规范 §9"禁止跨模块直接读取其他模块数据库表形成隐式耦合"）；
4. 白名单的**唯一事实来源**是 `backend/app/registry.py` 的 `TABLE_OWNER`（机器可检查，见 §12）。

## 7. Pydantic v2 域模型（TS-03.6）

### 7.1 分层与命名

| 层 | 位置 | 特征 |
|---|---|---|
| API 入参 schema | `app/<module>/schemas.py` 中 `*Create / *Update / *Request` | 严格校验，**无** `from_attributes`；是 MCP/REST 的唯一入参形态 |
| 领域/出参 schema | `app/<module>/schemas.py` 中 `*Read` | `ConfigDict(from_attributes=True)`，可从 ORM 实例构造；聚合字段由服务层组装 |
| 通用 schema | `app/common/schemas.py` | `ORMModel` 基类、`QualityInfo`、`ResponseEnvelope`、`ActorRef` 等跨域类型 |

> 约定：service 方法签名使用 schema 而非 ORM 实例（便于测试与解耦）；ORM 实例只在仓储层与"Read 构造"两处出现。

### 7.2 通用基类与 MCP 统一响应包络

```python
# backend/app/common/schemas.py

from decimal import Decimal
from typing import Any, Generic, TypeVar
from uuid import UUID

from pydantic import BaseModel, ConfigDict, Field

from app.common.enums import ActorType, DataQualityStatus

T = TypeVar("T")


class ORMModel(BaseModel):
    """出参基类：允许从 ORM 实例构造（from_attributes）。

    这是 ORM → Schema 的单向桥；Schema 绝不反向产生 ORM 状态（§1 分工）。
    """
    model_config = ConfigDict(from_attributes=True)


class QualityInfo(BaseModel):
    """统一数据质量块（ts01 MCP 包络：quality.status / score / flags）。"""
    status: DataQualityStatus
    score: Decimal = Field(ge=0, le=1)                       # quality_score ∈ [0,1] 冻结
    flags: list[str] = Field(default_factory=list)


class ProvenanceSummary(ORMModel):
    """包络内嵌 provenance 摘要（不泄漏完整记录）。"""
    provenance_id: UUID
    source: str
    provider: str
    observed_at: datetime
    retrieved_at: datetime
    quality_score: Decimal = Field(ge=0, le=1)


class ActorRef(BaseModel):
    """MCP 作者引用（ts01 create_thesis_revision 契约）。"""
    type: ActorType
    id: str


class ResponseEnvelope(BaseModel, Generic[T]):
    """MCP/API 统一响应包络（TS-01 冻结五要素：request_id / as_of / data / quality / provenance）。"""
    request_id: UUID
    as_of: datetime
    data: T
    quality: QualityInfo
    provenance: list[ProvenanceSummary] = Field(default_factory=list)
```

## 9. 序列化与版本（TS-03.8）

### 9.1 枚举：保持字符串值（而非 Python 成员名）

- `StrEnum.value` 即 DB 存储值与 JSON 输出值；**禁止输出 Python 成员名**（`X.B` 而非 `B`）；
- Pydantic v2 对枚举字段默认序列化为 `.value`（实测 `E(e=X.B).model_dump_json()` → `{"e":"B"}`）；
- 入参反序列化同理：`X("B")` 可还原成员，非法字符串 → 422；
- 与 ORM 读取值（`str`）配合：`DataQualityStatus(row.quality_status)` 显式转换。

### 9.2 金额 NUMERIC：Decimal 与 JSON 陷阱（实测结论）

| 操作 | 结果 |
|---|---|
| `model_dump()`（python 模式） | `Decimal('1.10')` 原样 |
| `model_dump(mode="json")` / `model_dump_json()` | **字符串** `"1.10"`（保精度） |
| `json.dumps(model_dump())` | **TypeError: Decimal is not JSON serializable** |

落地策略（冻结）：

1. 所有出参序列化统一走 `model_dump(mode="json")` / `model_dump_json()`，**禁止对 ORM 对象直接 `json.dumps`**；
2. API Contract（TS-05）必须把"金额字段 JSON 输出为字符串（精度安全）"作为显式契约并用 golden 测试锁定；若 Dashboard 需要数值，前端 `parseFloat` 或后端提供舍入到 2 位小数的数值视图字段；
3. JSONB 内嵌 Decimal 是**写库前必须解决**的陷阱（`json.dumps` 无法处理）：

```python
# 写 JSONB 前显式转换（示例：ETFMetricSnapshot 相关 JSONB 组装）
payload = {
    "nav": str(Decimal("1.2846")),       # → "1.2846"
    "premium": str(Decimal("0.0634")),   # → "0.0634"
}
row.result_json = payload                # JSONB 列只接受 JSON 原生类型
```


### 9.3 时间戳与时区

- 存储：`TIMESTAMPTZ`（UTC）；ORM 读回 `datetime` 带 `tzinfo=utc`；
- 出参：Pydantic 输出 ISO8601（`+00:00`）；**禁止输出 naive datetime**（Pydantic 对 naive 入参会告警/按配置拒绝）；
- 展示：Asia/Shanghai 由展示层转换；`as_of` 入参接受带时区 ISO8601，naive 入参按 Asia/Shanghai 解释后转 UTC（service 层统一，TS-05 锁定）；
- PIT 查询：`published_at <= as_of`（`as_of` 为 UTC 时点），业务日参数（`market_date` 等）用 `DATE` 列精确匹配（ts02 §9）。

### 9.4 JSONB 字段序列化策略

- `thesis_body` / `result_json` / `holdings_json` 等 JSONB 列在 Read schema 中声明为 `dict[str, Any]` / `list[dict]`，序列化原样透传；
- JSONB 键必须是字符串（Postgres 约束）；**禁止 UUID 作 JSON 键**（需先 `str(uuid)`）；
- JSONB 内部结构（如 `thesis_body` 的章节 schema、`result_json` 的 bear/base/bull 结构）**不在本文件冻结**——由 TS-04 Data Contract 定义（§13）。

### 9.5 版本相关

- `instrument.version` / `thesis_revisions.version`：整数单调；乐观并发语义见 §10；
- `engine_version`（valuation / etf_metric / position / portfolio snapshot）：语义化字符串（如 `valuation-engine/0.1.0`），**不得在业务逻辑中硬编码模型名**（冻结规范 §34）；
- Parquet 数据集版本（`ohlcva/v1/` 等）不在 Alembic 管理范围，由 TS-04 data-contracts 管理（ts02 §13.1）。

## 10. 服务层与仓储层建议（TS-03.9）

### 10.1 模式：薄 service + repository

- **service**：业务规则、状态机、事务边界、审计/provenance 同事务写入；不写 SQL 细节；
- **repository**：每张表/聚合的唯一数据访问点；**append-only 表的仓储只暴露 `create` 与只读查询，接口形态即纪律**（没有 `update/delete` 方法可调）；
- **单例 owner（ts01 所有权表）**：每张业务表恰好一个 authoritative writer——`LedgerService` 是 `portfolio_transactions` 唯一写者；`ThesisService` 是 thesis 唯一写者；`ValuationEngine` 是 `valuation_runs` 唯一写者；Hermes 一律走 typed command（MCP），绝不直写。

### 10.2 写路径示例：Thesis Revision（乐观并发 409）

```python
# backend/app/thesis/service.py（示意）
class ThesisService:
    """Thesis 域唯一写入口。Business Owner = Investor；Write Authority = ThesisService。"""

    def __init__(self, session: Session) -> None:
        self._session = session

    def create_revision(self, req: CreateThesisRevisionRequest) -> ThesisRevision:
        head = self._session.execute(
            select(Thesis.current_revision_id).where(Thesis.thesis_id == req.thesis_id)
        ).scalar_one_or_none()
        if head is None:
            raise EntityNotFound("thesis", req.thesis_id)
        if head != req.base_revision_id:
            raise DomainConflict("base_revision_id 已过期（不是当前 head）")     # 409（TS-01 冻结）

        thesis = self._session.get(Thesis, req.thesis_id)
        revision = ThesisRevision(
            thesis_id=req.thesis_id,
            version=self._next_version(thesis) + 1,
            thesis_body=req.thesis_body,
            change_reason=req.change_reason,
            authored_by=req.author.type.value,
            base_revision_id=req.base_revision_id,
            provenance_id=self._write_provenance(req.author),          # 同事务写 provenance
        )
        self._session.add(revision)
        self._session.flush()                                           # 取得 revision_id

        # 乐观并发：head 竞争更新（ts02 §12.3 冻结）；行数 0 → 409
        moved = self._session.execute(
            update(Thesis)
            .where(Thesis.thesis_id == req.thesis_id,
                   Thesis.current_revision_id == req.base_revision_id)
            .values(current_revision_id=revision.thesis_revision_id)
        )
        if moved.rowcount == 0:
            raise DomainConflict("并发冲突：head 已被其他事务移动")       # 409
        # assumptions / evidence_links / audit 同事务写入（示意略）
        return revision
```

### 11.2 命名与约束生成策略

### 11.3 append-only 触发器（DB 级兜底，ts02 §10.3）

```python
# 共享拒绝函数（0001 号 migration 创建一次）
op.execute("""
    CREATE OR REPLACE FUNCTION fn_reject_update() RETURNS trigger AS $$
    BEGIN
      RAISE EXCEPTION 'table % is append-only', TG_TABLE_NAME;
    END $$ LANGUAGE plpgsql;
""")

# 每张不可变表对应一个 migration 片段（示例：thesis_revisions）
def upgrade() -> None:
    op.create_table("thesis_revisions", ...)        # autogenerate 产出列定义
    op.execute("""
        CREATE TRIGGER trg_thesis_revisions_no_update
        BEFORE UPDATE OR DELETE ON thesis_revisions
        FOR EACH ROW EXECUTE FUNCTION fn_reject_update();
    """)

def downgrade() -> None:
    op.execute("DROP TRIGGER IF EXISTS trg_thesis_revisions_no_update ON thesis_revisions")
    op.drop_table("thesis_revisions")
```


**启用触发器的不可变表清单**（与 ts02 §10.1 一致）：`provenance_records`、`thesis_revisions`、`portfolio_transactions`、`valuation_runs`、`valuation_assumptions`、`valuation_input_refs`、`evidence_items`、`evidence_links`、`audit_events`、`outbox_events`、`position_snapshots`、`portfolio_snapshots`、`thesis_events`、`research_events`。
