# Hermes Investment Office Technical Specification：MCP Contract 研究报告

## 执行摘要

本报告将 **TS-07 MCP Contract** 定义为 Hermes Investment Office 中 **Hermes 控制平面与 Investment Backend 事实/计算平面之间唯一数据访问通道**的完整契约。主要输入是 [TS-01 Domain Model Specification 研究报告](ts01.md)（§1.6 初始关系模型与 MCP 合同）、[TS-02 PostgreSQL ERD 研究报告](ts02.md)（物理表结构）、[TS-06 Engine Contract 研究报告](ts06.md)（§3.8 run_valuation 触发语义、§2.3.1 引擎输出包络、§2.2.3 输入质量门禁）与 [《后端架构冻结规范 v1.0 Consolidated》](Hermes_Investment_Office_后端架构冻结规范_v1.0_Consolidated.md)（§31–§36：Investment Profile、Hermes MCP Contract、权限模型、Model Routing、Job System、Freshness Contract）。

TS-07 的职责**不是重新发明 MCP 工具**，而是把冻结规范 §32 的八组工具清单与 ts01 §1.6 的五个雏形工具扩展为**可施工、可测试、可审计的完整契约**，并落地三件冻结规范要求但尚未细化的东西：

```text
① 传输/端点/包络契约（StreamableHTTP、request_id 贯穿、统一响应包络）
② 权限模型落地（五级权限 × 28 工具映射、ACCOUNT_WRITE 人工入口边界、越权拒绝）
③ 错误契约（统一错误包络、错误码清单、幂等与重试语义）
```

### 核心设计结论

> **MCP 是 Hermes 与 Backend 之间唯一的数据访问通道（`Hermes → MCP → Backend → Database`）。Hermes 只消费高层、Typed、受控的 MCP Tool；MCP 面禁止暴露 `raw_sql()` 等无约束接口；Hermes 在物理上无法触达数据库（冻结规范 §3.1 / §4.4 / §32）。**

由此派生的冻结结论：

1. **Typed Tools 原则**：每个工具都有固定输入 schema、固定输出 schema、固定权限级别、固定错误码集合。Hermes 侧没有"自由查询"通道；身份一律用 `instrument_id / thesis_id / portfolio_id / valuation_run_id / evidence_id / job_run_id` 等稳定 UUID，`resolve_instrument` 是唯一的"符号/名称 → 稳定身份"入口。
2. **包络统一**：所有工具共享 ts01 §1.6 的统一响应包络 `{request_id, as_of, data, quality, provenance}`；decision-sensitive 工具额外强制携带 `freshness`（域级状态，枚举 `OK/WARNING/STALE/FAILED`，对齐冻结规范 §36.2 / ts04 §7.1）。
3. **Freshness 是行为门禁，不是装饰字段**：`data_freshness != OK` 时，Hermes 禁止生成 Buy/Hold/Sell 建议、更新 Thesis、创建 Trade Proposal（冻结规范 §36.3）；MCP 层在后端同步拒绝这三类写操作（`FRESHNESS_GATE`），形成"Hermes 纪律 + Backend 强制"双保险。
4. **权限五级、越权即拒**：READ / RESEARCH_WRITE / PROPOSAL_WRITE 是 Hermes 实际可触达的三级；`ACCOUNT_WRITE` 只存在于人工入口（localhost admin API），**不在 MCP 暴露面**；`EXECUTION` 在 v0.1 不存在（禁止 Broker API）。三层执行保障：网络隔离 → 工具集约束（`enabled_toolsets=web+mcp`）→ 后端 MCP 权限分级。
5. **同步计算有上限**：`run_valuation` 冻结为同步 + 30s 超时（ts06 §3.8）；超时转 job，返回 `202 JOB_TRIGGERED` + `job_run_id`，Hermes 通过 `get_job_status` 轮询——MCP 通道永不被长任务阻塞。

## 1. 传输与端点契约（TS-07.1）

### 1.1 传输层：StreamableHTTP

- **协议**：MCP（Model Context Protocol）HTTP transport，采用 **StreamableHTTP** 传输方式（冻结规范 §31.1：FastAPI 内嵌 MCP 端点）。单请求-单响应为主，不支持（也不需要）SSE 流式长连接；v0.1 不引入 MQ / WebSocket（冻结规范 §7）。
- **端点**：`http://127.0.0.1:8000/mcp`（Backend 的 MCP/API 端口只绑定 127.0.0.1，单机部署）。
- **消息载体**：JSON-RPC 2.0。协议层负责传输与路由，业务语义全部放在工具输出中（§1.5 包络）。
- **会话**：v0.1 无状态；每个请求独立鉴权（当前为 localhost 信任边界，§1.2）。
- **工具发现**：Hermes 侧通过 MCP `tools/list` 获取工具清单；**工具清单必须与 §2 冻结契约一致**（架构测试白名单，§7.1），禁止出现清单外工具。

**协议层消息结构（JSON-RPC 2.0）：**

```jsonc
// 请求
{
  "jsonrpc": "2.0",
  "id": 1,                       // 客户端请求标识（协议层）
  "method": "tools/call",
  "params": {
    "name": "get_thesis",
    "arguments": {
      "thesis_id": "7b2c...210",
      "as_of": "2026-08-23T10:30:00+08:00"
    }
  }
}

// 成功响应（协议层 result 即业务包络，见 §1.5）
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "request_id": "9f31...8c2a",
    "as_of": "2026-08-23T10:30:00+08:00",
    "data": { },
    "quality": { "status": "VERIFIED", "score": 0.97, "flags": [] },
    "provenance": [ ]
  }
}

// 协议层错误（传输/路由/序列化错误；业务错误不进这里，见 §4）
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32602,              // MCP/JSON-RPC 标准码
    "message": "Invalid params: thesis_id is required"
  }
}
```

**两层错误的分工（冻结）：**

| 层 | 错误载体 | 覆盖范围 | 示例 |
|---|---|---|---|
| 协议层（JSON-RPC） | `error: {code, message}` | 传输错误、方法不存在、参数序列化错误、未知工具 | `-32601 Method not found`（工具不在白名单） |
| 业务层（包络） | `error: {code, message, field?, request_id}`（§4.1） | 领域错误：冲突、权限、数据质量、freshness、缺失输入、job 触发 | `DOMAIN_CONFLICT`、`FRESHNESS_GATE`、`JOB_TRIGGERED` |

> 设计要点：`JOB_TRIGGERED`（202）是**业务层响应**（包络内 `error` 或 `data.job_run_id` + 状态标注），不是协议层错误——调用方应将其视为"已受理、转异步"的正常结果。

### 1.2 端点部署与认证边界

**v0.1 当前部署（冻结规范 §33.3）：**

```text
single machine
localhost
无 MCP Token
```

- Backend MCP/API 端口绑定 `127.0.0.1`，Hermes 与 Backend 同机运行；
- 认证边界 = **localhost 信任边界**：无 token、无用户级认证；权限分级（§3）按调用方上下文（Hermes profile）在后端 MCP 层执行；
- 组合数据隐私要求单机绑定（冻结规范 §40 同理由）。

**未来跨机部署必须增加（冻结规范 §33.3，ADR 前置）：**

```text
API Token          —— 每次 MCP 请求携带 Bearer token；服务端校验 + 轮换策略
Authentication Layer —— 独立认证层（非业务代码内联校验）
Request Audit      —— 认证失败/越权尝试必须落 audit_events（action='LOGIN' / 'PERMISSION_DENIED'）
```

TS-07 同时规定：即使未来跨机，**认证层也不改变本节工具契约与权限语义**——token 只解决"谁在调用"，不解决"能调什么"（后者由 §3 权限矩阵决定）。

### 1.3 request_id 贯穿（审计关联）

- **生成**：Backend MCP 层为每个业务请求生成 `request_id`（UUID）。若客户端在 arguments 中携带幂等键（`request_id` 或 `client_request_id`），服务端**回显**该值，避免客户端-服务端 id 分裂。
- **贯穿范围**：
  - 响应包络顶层 `request_id`（§1.5）；
  - 业务错误包络 `error.request_id`（§4.1）；
  - 落库时写入 `audit_events.request_id`（ts02 §8.3，列已存在），使 **MCP 请求 ↔ 审计事件** 可双向追溯；
  - 引擎输出包络（ts06 §2.3.1）与 job 参数（`job_runs.params.request_id`）同样携带。
- **验收语义**：给定一个 MCP 请求的 `request_id`，审计查询必须能列出该请求触发的全部 `audit_events`（含 actor、action、entity、before/after hash），以及（如转 job）对应的 `job_runs` 记录。

### 1.4 统一响应包络（继承 ts01 §1.6）

所有工具的成功响应共享统一包络。完整 schema 定义：

```text
MCPBusinessEnvelope
├── request_id      : UUID（必填）服务端生成或回显客户端幂等键；写入 audit_events.request_id
├── as_of           : TIMESTAMPTZ（decision-sensitive 必填；其余工具可选）数据语义时点
├── data            : object（必填，业务错误时省略）工具专属载荷（§2 各工具定义）
├── quality         : object（必填）
│     ├── status    : DataQualityStatus   = VERIFIED | ACCEPTABLE | STALE | CONFLICT | REJECTED
│     ├── score     : number(0-1) | null  质量评分（引擎派生结果=1.0；聚合/身份类可 null）
│     └── flags     : string[]            质量 flag（ts04 §6.3 编码清单）
├── provenance      : ProvenanceRef[]（decision-sensitive 必填且非空）血缘数组
└── freshness       : FreshnessPayload（decision-sensitive 工具必填）域级新鲜度
```

`ProvenanceRef`（精简引用，完整字段在 `provenance_records`）：

```jsonc
{
  "provenance_id": "uuid",
  "source_kind": "OFFICIAL_FILING | EXCHANGE | PROVIDER | HUMAN | HERMES | DERIVED_ENGINE",
  "source": "string",
  "provider": "string",
  "observed_at": "timestamp",
  "retrieved_at": "timestamp",
  "as_of_date": "date",
  "quality_score": 0.97,
  "quality_status": "VERIFIED",
  "quality_flags": [],
  "fallback_used": false,
  "transform_version": "market-normalizer/0.1.0"
}
```

`FreshnessPayload`（对齐 ts04 §7.2 `daily_contexts.data_freshness` 结构）：

```jsonc
{
  "overall": "OK | WARNING | STALE | FAILED",        // = worst(各域)
  "domains": {
    "market":       { "status": "OK", "latest_point": "2026-08-21", "lag": {"sessions": 0, "days": 0} },
    "fundamental":  { "status": "OK", "latest_sync_at": "..." },
    "etf_nav":      { "status": "OK", "latest_nav_date": "2026-08-20" },
    "etf_holdings": { "status": "OK", "latest_report_period": "2026-06-30" },
    "index":        { "status": "OK", "latest_us_session": "2026-08-20" },
    "fx":           { "status": "OK", "latest_as_of": "..." },
    "quota":        { "status": "OK", "quota_status": "OPEN" }
  },
  "stale_provenance_ids": [],
  "required_action": null
}
```

**包络强制字段矩阵（按工具类别，冻结）：**

| 工具类别 | request_id | as_of | data | quality | provenance | freshness |
|---|---|---|---|---|---|---|
| 身份解析（`resolve_instrument`） | ✔ | ✔（回显请求时点） | ✔ | ✔ | 建议携带（`internal` 引用） | — |
| 事实读取（market/fundamental/filings/evidence） | ✔ | ✔ | ✔ | ✔ | decision-sensitive 必填 | decision-sensitive 必填 |
| 组合/风险读取（portfolio/positions/exposure/risk） | ✔ | ✔ | ✔ | ✔ | **必填非空** | **必填** |
| 估值读取（latest/history） | ✔ | ✔ | ✔ | ✔ | **必填非空** | **必填** |
| 引擎触发（`run_valuation`） | ✔ | ✔ | ✔ | ✔ | **必填非空**（DERIVED_ENGINE） | **必填** |
| Thesis 读取/写入 | ✔ | ✔ | ✔ | ✔ | 读：必填；写：建议 | 写：**必填**（门禁） |
| 研究/简报写入 | ✔ | — | ✔ | ✔ | 建议 | — |
| job 触发/查询（sync_*、get_job_status） | ✔ | — | ✔ | ✔ | 建议 | — |

> **枚举一致性（硬约束）**：包络 `quality.status` 只允许 ts01 冻结的 `VERIFIED/ACCEPTABLE/STALE/CONFLICT/REJECTED`；`freshness.*.status` 只允许冻结规范 §36.2 / ts04 §7.1 的 `OK/WARNING/STALE/FAILED`。ts01 §1.6 示例中出现的 `FRESH` 是展示性文字，**不是合法枚举值**（ts04 已裁决），TS-07 一律使用 `OK`。

### 1.5 freshness 联动：Hermes 行为门禁（冻结规范 §36.3 落地）

decision-sensitive 返回值必须携带 `freshness`。Hermes 侧消费规则（固化进 `investment-runtime-policy` skill，§6.1）：

| `freshness.overall` | Hermes 行为 |
|---|---|
| `OK` | 正常生成投资判断 |
| `WARNING` | 允许生成判断但**必须带数据异常标注**；禁止把 WARNING 掩盖为 OK |
| `STALE` | **禁止** Buy/Hold/Sell 建议、Thesis 更新、Trade Proposal（§36.3 三类写操作）；**允许**数据异常报告、请求重同步（`sync_*` / `get_job_status`）、标记 Attention Item |
| `FAILED` | Hermes 跳过 LLM 阶段（非交易日或同步失败，冻结规范 §31.1）；仅允许异常报告与重同步请求 |

**MCP 后端侧的强制（与 Hermes 纪律形成双保险）**：以下三类写操作在 `data_freshness != OK`（任意域非 OK）时由后端直接拒绝：

```text
create_thesis_revision      → 409 FRESHNESS_GATE
record_thesis_review        → 409 FRESHNESS_GATE   （review 结论会影响 health/判断）
update_thesis_assumption    → 409 FRESHNESS_GATE
create_trade_proposal       → 409 FRESHNESS_GATE
```

> 例外（冻结）：`save_research_note` / `save_daily_brief` 是研究/简报记录，**不受 freshness 门禁**（记录事实与判断历史本身合法；但 brief 内容不得含被门禁禁止的判断类别——由 Hermes skill 纪律约束，Backend 不做内容审查）。Buy/Hold/Sell 建议不落 MCP 写工具（Hermes 对话输出），门禁由 skill 层执行。

## 2. 工具契约（TS-07.2）

### 2.0 通用约定（全部工具共享）

1. **身份参数**：除 `resolve_instrument` 外，所有工具只接受稳定 UUID 身份（`instrument_id / thesis_id / portfolio_id / valuation_run_id / evidence_id / job_run_id`）。禁止传 provider symbol、表名、SQL 片段（§5.4）。
2. **as_of 语义**：所有 `get_*` 工具支持可选 `as_of`（TIMESTAMPTZ）；缺省 = "当前可见最新"。历史查询必须 PIT 过滤（`published_at <= as_of` / `trade_date <= as_of` / `snapshot_date <= as_of` / `created_at <= as_of`，ts04 §5.2），**禁止 look-ahead**（§5.1）。
3. **分页**：列表类工具统一 `limit`（默认 50，上限 200）+ `offset`；响应携带 `total` 与 `next_offset`（无更多时 `next_offset=null`）。
4. **provenance 简写**：§2 各工具输出示例中 provenance 只给 1–2 条引用；实际响应按 §1.4 `ProvenanceRef` 完整字段返回。
5. **错误**：所有工具失败时返回 §4.1 统一错误包络；§2 每工具列出其**可能触发的错误码**（全量清单见 §4.2）。
6. **权限**：§2 每工具标注权限级别；越权调用 → `403 PERMISSION_DENIED`（§3.5）。
7. **引擎版本可见性**：凡引擎派生输出（估值、组合、风险、ETF 指标）必须在 `data` 内携带 `engine_version` 与 `input_hash`（ts06 §2.1.2 / §2.2.4），Hermes 侧不得自行计算等价指标（§4.2 冻结规范 LLM 算术禁令）。
8. **JSON 数值**：金额 `NUMERIC(18,4)` 语义、比率 0–1 小数（ts02 §1.2）；响应中禁止浮点歧义（黄金值定点语义）。

**用途**：为 Thesis 追加不可变 revision（version+1），可携带假设变更与证据关联。**并发冲突规则（ts01 §1.6 冻结）**：`base_revision_id != current_revision_id → 409 DOMAIN_CONFLICT`，防止基于过期版本创建新版本。

- **权限**：**RESEARCH_WRITE**（规范澄清，§8 #2）
- **错误码**：`DOMAIN_CONFLICT`（base 过期）、`FRESHNESS_GATE`（data_freshness != OK 禁止更新 Thesis）、`NOT_FOUND`、`INVALID_ARGUMENT`、`PERMISSION_DENIED`
- **provenance 要求**：写 `thesis_revisions.provenance_id`（`source_kind=HERMES`）；响应 provenance 引用创建事件

**输入（ts01 §1.6 原样）：**

```jsonc
{
  "request_id": "uuid",                    // 幂等键
  "thesis_id": "uuid",
  "base_revision_id": "uuid",
  "change_reason": "2026H1 operating results changed base-case assumption",
  "thesis_body": { "narrative": "…", "structure": {} },
  "assumption_changes": [
    { "action": "UPDATE", "assumption_id": "uuid", "status": "WARNING", "note": "H1 营收低于预期" }
  ],
  "evidence_ids": ["uuid", "uuid"],
  "author": { "type": "HERMES", "id": "hermes" }
}
```

**输出 `data`：**

```jsonc
{
  "thesis_id": "uuid",
  "revision_id": "uuid",
  "version": 19,
  "lifecycle_status": "ACTIVE",
  "health_status": "WARNING",
  "created_at": "2026-08-23T10:45:00+08:00"
}
```

**冲突（完整示例）：**

```jsonc
{
  "request_id": "uuid",
  "error": {
    "code": "DOMAIN_CONFLICT",
    "message": "base_revision_id 不是当前 head revision（current=20，base=18）",
    "field": "base_revision_id",
    "request_id": "uuid"
  }
}
```

> 落库事务（ts02 §12.1）：revision + assumption_changes + evidence_links + audit + provenance **原子提交**；`theses.current_revision_id` 移动用乐观并发（`WHERE current_revision_id=$base`，影响行数 0 → 409，ts02 §12.3）。**Freshness 门禁**：Thesis 更新是 §36.3 禁止类操作。

## 3. 权限模型落地（TS-07.3）

### 3.1 五级权限定义（冻结规范 §33.1 原样）

| 级别 | 语义 | Hermes 可触达？ |
|---|---|---|
| **READ** | 读市场/基本面/组合/研究/Thesis/估值/风险数据；幂等触发同步 job | ✔ |
| **RESEARCH_WRITE** | 保存研究笔记、记录 Thesis 复核、更新 Thesis 假设（+ 本报告澄清：创建 Thesis revision、保存日报） | ✔ |
| **PROPOSAL_WRITE** | 创建 Trade Proposal（REAL 组合下最高权限对象） | ✔ |
| **ACCOUNT_WRITE** | 记录真实交易、修改真实现金、修改真实账户 —— **只属于人工入口（localhost admin API）** | ✘（MCP 面不存在） |
| **EXECUTION** | v0.1 **不存在**；禁止 Broker API 自动执行 | ✘ |

### 3.2 工具 × 权限映射表（冻结，TS-08 权限矩阵测试的输入）

| 权限 | 工具 |
|---|---|
| **READ**（19+1） | `resolve_instrument`、`get_market_snapshot`、`get_price_history`、`get_market_metrics`、`sync_market_data`*、`get_fundamentals`、`get_financial_history`、`get_latest_filings`、`sync_fundamentals`*、`run_valuation`*、`get_latest_valuation`、`get_valuation_history`、`get_portfolio`、`get_positions`、`get_portfolio_exposure`、`get_portfolio_risk`、`get_research_context`、`get_evidence`、`search_research`、`get_thesis`、`get_daily_context`、`get_job_status` |
| **RESEARCH_WRITE**（5） | `save_research_note`、`record_thesis_review`、`update_thesis_assumption`、`create_thesis_revision`**、`save_daily_brief`** |
| **PROPOSAL_WRITE**（1） | `create_trade_proposal` |
| **ACCOUNT_WRITE**（3，**MCP 面禁止**） | `record_real_transaction`、`modify_real_cash`、`modify_real_account` —— 不在 MCP 工具注册表，无对应 MCP tool |
| **EXECUTION**（0） | 不存在 |

> \* 标注说明：`sync_market_data`/`sync_fundamentals` 触发 job 但**不写业务 SoT**（落库走 Backend Scheduler/Data Service 所有权），归 READ 级（与 ts05 §8.1 一致）；`run_valuation` 创建 ValuationRun 但落库走引擎所有权，ts06 §3.8 冻结为 READ 级。三者都以"计算/入队请求"而非"业务状态写"论处。
>
> \*\* 规范澄清：冻结规范 §33.1 RESEARCH_WRITE 列举了 `save_research_note / record_thesis_review / update_thesis_assumption`，未显式列举 `create_thesis_revision` 与 `save_daily_brief`。TS-07 裁决两者归 RESEARCH_WRITE（创建 Thesis revision 与保存日报都是"研究产物持久化"，远低于账户写权限）；该澄清需 ADR 回写冻结规范 §33.1（§8 #2）。

### 3.3 ACCOUNT_WRITE 人工入口边界（MCP 面禁止）

**冻结规范 §25.2 / §33.1 的落地：**

```text
MCP 暴露面（Hermes 可触达）                 人工入口（localhost admin API，用户确认）
─────────────────────────                  ─────────────────────────────────────
create_trade_proposal                      record_real_transaction
  （status 最多到 PROPOSED）        ────►   modify_real_cash
                                            modify_real_account
                                            trade_proposals: APPROVED → EXECUTED
                                              （写 portfolio_transactions +
                                                回填 executed_transaction_id）
```

- **MCP 工具注册表中不存在** `record_real_transaction` / `modify_real_cash` / `modify_real_account`——调用任何不存在的工具 → 协议层 `-32601 Method not found`（架构测试 #5 白名单拦截）；
- 真实交易的落账只能由人工入口完成（Dashboard/CLI 手动确认 → 后端自身落账，原子事务 + audit + provenance，ts06 §5.8.2）；
- **任何自动化路径（Hermes 会话、Hermes Cron、Job、引擎）写 REAL 交易 = 架构违规**，TS-08 架构测试 #6 拦截；
- 人工入口与 MCP 是**两个独立通道**：人工入口不经过 MCP 工具（它是受保护的后端 admin API，仅监听 localhost），因此不存在"通过 MCP 伪装人工"的路径。

### 3.4 三层执行保障（冻结规范 §33.2 落地）

| 层 | 机制 | 内容 |
|---|---|---|
| **第 1 层：网络隔离（物理）** | 数据库容器内部网络 | PostgreSQL/DuckDB 数据目录只暴露给 Backend Container；不映射端口到宿主机；Hermes terminal 物理上无法触达数据库（§4.4）。**Hermes → MCP → Backend → Database 是唯一路径** |
| **第 2 层：工具集约束（Hermes 侧）** | `enabled_toolsets` | 日报 cron 的 `enabled_toolsets = web + mcp`（不给 terminal/file），作为权限模型的运行时补充（§31.1） |
| **第 3 层：MCP 权限分级（Backend 侧）** | 后端 MCP 层权限校验 | 每个工具按 §3.2 矩阵校验调用方上下文权限；越权 → `403 PERMISSION_DENIED`；未知工具 → 协议层拒绝 |

> 日常会话纪律由 `investment-runtime-policy` skill 承载（§6.1），构成逻辑上的第 4 层（非物理强制）。

### 3.5 越权调用 → typed error

```jsonc
{
  "request_id": "uuid",
  "error": {
    "code": "PERMISSION_DENIED",
    "message": "工具 create_trade_proposal 需要 PROPOSAL_WRITE 权限，当前上下文仅 READ",
    "request_id": "uuid"
  }
}
```

- 越权尝试必须落 `audit_events`（`action='PERMISSION_DENIED'`，`request_id` 关联），供安全审计（跨机部署后这是 §1.2 Request Audit 的输入）；
- 权限校验在**工具执行前**完成（无副作用泄漏：越权调用不得执行任何计算或落库）；
- v0.1 localhost 信任边界下，"调用方上下文"= Hermes investment profile；未来引入用户/会话级身份后，矩阵不变，仅身份来源变化（§1.2）。

## 4. 错误契约（TS-07.4）

### 4.1 统一错误包络

所有业务错误返回统一结构（与成功包络互斥：有 `error` 则无 `data`）：

```jsonc
{
  "request_id": "uuid",                     // 贯穿（§1.3）
  "as_of": "2026-08-23T10:30:00+08:00",     // 可选：有语义时点的错误携带
  "error": {
    "code": "DOMAIN_CONFLICT",
    "message": "base_revision_id 不是当前 head revision",
    "field": "base_revision_id",            // 可选：定位到输入字段
    "request_id": "uuid"                    // 与顶层一致，冗余便于日志侧消费
  }
}
```

契约规则：

1. `error.code` 必须来自 §4.2 冻结清单；禁止返回裸字符串/异常消息；
2. `message` 不得泄漏 SQL、表名、provider symbol、内部堆栈（§4.5）；
3. 业务错误落在**业务层包络**（JSON-RPC result 内），协议层 error 只用于传输/路由错误（§1.1 两层分工）；
4. 错误必须可恢复判断：调用方能精确知道"缺什么、为什么失败、如何恢复"（ts06 §2.4.1 契约规则 #1）。

### 4.2 错误码清单（冻结）

| code | HTTP 等价 | 触发场景 | 关联工具 |
|---|---|---|---|
| `INVALID_ARGUMENT` | 400 | 参数缺失/格式错/枚举越界/身份为空 | 全部 |
| `PERMISSION_DENIED` | 403 | 越权调用（§3.5） | 全部 |
| `NOT_FOUND` | 404 | instrument/thesis/portfolio/evidence/job/context 不存在 | 全部 get/写工具 |
| `DOMAIN_CONFLICT` | 409 | `base_revision_id != current`；thesis head 并发竞争；proposal 非法状态迁移；幂等冲突 | `create_thesis_revision`、`update_thesis_assumption`、`create_trade_proposal` |
| `INVALID_PROPOSAL_TRANSITION` | 409 | trade_proposals 状态机非法迁移（ts06 §5.8.2） | `create_trade_proposal` |
| `INPUT_DATA_QUALITY_BLOCKED` | 409 | 输入含 `CONFLICT/REJECTED`（ts06 §2.4.2 映射） | `run_valuation`、`get_market_snapshot`、组合/风险读取 |
| `STALE_INPUT_REJECTED` | 409 | decision-sensitive 计算遇到 STALE 输入（ts06 §2.2.3：只允许 PIT 历史复现，禁止当前决策） | `run_valuation`、`get_market_metrics`、`get_portfolio_risk`、`get_portfolio_exposure` |
| `FRESHNESS_GATE` | 409 | `data_freshness != OK` 时三类写操作（§1.5 / §36.3） | `create_thesis_revision`、`record_thesis_review`、`update_thesis_assumption`、`create_trade_proposal` |
| `INVALID_INPUT` | 422 | 值非法（负价格、wacc<=0、单位不符、CN_ETF 传 run_valuation） | `run_valuation`、`get_fundamentals`（metric 清单外）等 |
| `MISSING_VALUATION_INPUT` | 422 | 估值必需假设/输入缺失（ts01 §1.6 对齐；run 状态 `BLOCKED_MISSING_INPUT`） | `run_valuation` |
| `UNSUPPORTED_MODEL_TYPE` | 422 | model_type 不在 `DCF/DDM/OWNER_EARNINGS/COMPARABLE/SCENARIO` | `run_valuation` |
| `TERMINAL_VALUE_UNDEFINED` | 422 | `terminal_growth >= wacc`（终值未定义，ts06 §3.5.2） | `run_valuation` |
| `TERMINAL_VALUE_CROSSCHECK_FAILED` | 422（或 WARNING 降级） | 终值双方法交叉验证失败（配置决定二选一，ts06 §3.5.2） | `run_valuation` |
| `JOB_TRIGGERED` | 202 | 同步超时转 job（不是错误，是异步受理信号） | `run_valuation` |
| `JOB_NOT_FOUND` | 404 | job_run_id 不存在 | `get_job_status` |
| `ENGINE_INTERNAL_ERROR` | 500 | 引擎未知异常（audit 必记录；禁止吞异常，ts06 E7） | `run_valuation`、组合/风险读取 |

**错误码优先级（同一请求多条件命中时）：** `PERMISSION_DENIED` > `FRESHNESS_GATE` > `INPUT_DATA_QUALITY_BLOCKED`/`STALE_INPUT_REJECTED` > `DOMAIN_CONFLICT` > `INVALID_INPUT`/`MISSING_VALUATION_INPUT`/`NOT_FOUND` > `INVALID_ARGUMENT`。

### 4.3 缺口语义不是错误（冻结，ts02 §9.4 / ts06 §2.4.1）

| 情况 | 表达方式 | 禁止 |
|---|---|---|
| 财报"该披露尚未披露" | 无行 / 空序列 | 抛异常、报 FAILED |
| 停牌 / 无成交 | `quality_flags=['GAP_BAR']` / `NO_TRADING` | 抛异常 |
| QDII 时间对齐失败 | `premium_discount=null` + `NAV_TIME_ALIGNMENT_FAILED` | 返回假精确值 |
| 相关性窗口样本不足 | `null` + `INSUFFICIENT_HISTORY` flag | 抛异常中断 |
| 非交易日无 daily_context | `NOT_FOUND`（Hermes 据此跳过 LLM 阶段） | 自行构造上下文 |

### 4.4 幂等与重试语义（冻结）

| 工具类别 | 幂等策略 | 重试安全 |
|---|---|---|
| `get_*`（全部只读） | 天然幂等（PIT 查询无副作用） | ✔ 任意重试 |
| `sync_market_data` / `sync_fundamentals` | 参数指纹去重 + 覆盖区间检查 + upsert-by-supersede（ts05 §8.2） | ✔ 重复触发不产生重复数据/不重复拉取 |
| `run_valuation` | 幂等键 = `request_id`：同一 request_id 重复提交 → 返回同一 run；不同 request_id 相同参数且既有 COMPLETED run 覆盖同一 as_of → 返回既有 run + `quality_flags=['DUPLICATE_REQUEST_RETURNED_EXISTING']`（不创建重复 Run） | ✔ 网络重试安全 |
| `create_thesis_revision` | 幂等键 = `request_id`：重复提交返回既有 revision；base 竞争由乐观并发 → `409 DOMAIN_CONFLICT` | ✔ 重试前必须重新读取 head |
| `create_trade_proposal` | 幂等键 = `request_id`：重复提交返回既有 proposal | ✔ 网络重试安全 |
| `save_daily_brief` / `save_research_note` | `market_date`/`client_request_id` 幂等 | ✔ |

**重试纪律：**

1. 网络层重试（超时/5xx）安全——除估值外全部工具无副作用（run_valuation 靠幂等键兜底）；
2. 业务错误（4xx）**不自动重试**，必须按 error.code 修复后重试；
3. `JOB_TRIGGERED` 后通过 `get_job_status` 轮询（间隔 ≥5s），**禁止在 MCP 层 sleep/忙等**（ts05 §8.2）；
4. 同步 job 失败 → `job_runs.error` 记录 typed error 码 + 消息；下一调度周期重试，避免无限循环（ts05 §5.4）。

### 4.5 错误消息安全（冻结）

- 错误消息禁止包含：SQL 片段、表名（`thesis_revisions` 等）、Provider symbol（`600519.SH`）、内部堆栈、engine 内部变量；
- 允许包含：业务对象身份（`thesis_id` 等 UUID）、字段名、enum 合法值、修复指引（"补足 wacc 后重试"）；
- 架构测试 #5 覆盖：MCP 模块不得 import `providers.*` / 不得出现表名常量（ts05 §8.1）。

## 5. PIT 与 provenance 强制（TS-07.5）

### 5.1 as_of 全工具支持（冻结）

```text
get_market_snapshot / get_price_history / get_market_metrics    → trade_date <= as_of（ohlcva）
get_fundamentals / get_financial_history                        → published_at <= as_of（financial_facts）
get_latest_valuation / get_valuation_history                    → run.as_of <= 查询时点 AND status='COMPLETED'
get_portfolio / get_positions / get_portfolio_exposure / risk   → snapshot_date <= as_of（position/portfolio snapshots）
get_thesis                                                      → thesis_revisions.created_at <= as_of（PIT 版本）
get_daily_context                                               → market_date 定位（无历史回放语义）
```

- **look-ahead 防护（ts04 §5.4）**：可见性判定只用 `published_at`（/`created_at`/`snapshot_date`），`retrieved_at`、`period_end`、`ingested_at` 不得参与；
- **重述语义**：`is_restated=true` 的新行不影响历史 as_of 查询——历史查询看到披露时点旧值，重述值只在 `as_of >= 重述披露时点` 后可见（ts04 §5.4 #4）；
- 缺省 `as_of` = 当前可见最新（"现查 MCP"默认行为，§6.1 规则 #6）。

### 5.2 get_thesis(as_of) 的 PIT 可见性（ts01 §1.6 验收）

- `as_of` 查询必须返回 **PIT 可见版本**（`thesis_revisions.created_at <= as_of` 取最近），禁止永远返回今天的 revision；
- 假设、证据、复核的可见性同样按 as_of 过滤（assumption 声明于某 revision、evidence `published_at`）；
- 验收测试：给定历史 `as_of`，`get_thesis` 返回的 version 必须等于"该时点 head"，黄金测试断言（§7.5）。

### 5.3 decision-sensitive 强制 provenance（冻结）

下列返回值**必须**携带非空 `provenance` 数组（缺任一 → 输出层拒绝返回，架构测试拦截，ts06 §2.3.2）：

```text
get_market_snapshot / get_market_metrics（价格、ETF 指标）
get_fundamentals / get_financial_history（财务事实）
run_valuation / get_latest_valuation / get_valuation_history（估值全部结果）
get_portfolio / get_positions / get_portfolio_exposure / get_portfolio_risk（组合/风险）
get_thesis（revision/assumption/evidence 血缘）
get_daily_context（attention 规则 provenance + stale_provenance_ids）
```

- 引擎派生输出：`source_kind=DERIVED_ENGINE`、`provider=internal`、`transform_version=engine_version`（ts06 §2.3.1）；
- 输出 provenance 数组是**精简引用**（`ProvenanceRef`），完整血缘可凭 `provenance_id` 在 Backend 查询；
- **禁止无 provenance 的 decision-sensitive 输出**；`CONFLICT/REJECTED` 输入 → 拒绝产出 VERIFIED 结果（ts01 §1 验证规则）。

### 5.4 MCP 面禁止泄漏（硬约束）

| 禁止 | 原因 | 对应机制 |
|---|---|---|
| `raw_sql()` / 任意 SQL 工具 | 无约束接口破坏 Typed Tools 原则（冻结规范 §32） | 架构测试 #5 白名单；工具注册表静态枚举 |
| 表名 / 列名泄漏（`thesis_revisions` 等） | 破坏 Backend 演化自由（改表名不破坏契约） | 错误消息安全（§4.5）；包络只含业务字段 |
| Provider symbol / provider schema 泄漏 | ts05 §P1：API/MCP 无 provider 字段 | `resolve_instrument` 是唯一字符串入口，输出不回显 provider |
| 裸 Parquet 路径 / 存储细节 | ts04 §2.6.1：业务代码禁止硬编码版本路径 | 工具只暴露业务查询参数 |

**工具契约只认稳定身份**：`instrument_id / thesis_id / portfolio_id / valuation_run_id / evidence_id / job_run_id / daily_context_id`（UUID）。任何"用代码直接查"的需求必须先过 `resolve_instrument`。

### 5.5 QDII 四日期与时序对齐在 MCP 的体现

- `get_market_metrics`（ETF）必须同时携带：`market_date`（A 股）、`nav_date`（基金估值日）、`underlying_session_date`（美股交易日）、`fx_as_of`（ts02 §4.6 冻结），禁止只存单一 `as_of`；
- 对齐失败一律 `null + flag`（`NAV_TIME_ALIGNMENT_FAILED` / `FX_TIME_ALIGNMENT_FAILED`），禁止返回假精确值（ts06 §4.7）；
- 对齐锚点来自 `trading_calendar`（Backend 侧），**禁止 Hermes 侧重复实现交易日历**（冻结规范 §31.1）；
- `quota_status` 是事件状态（来自公告 provenance），禁止从溢价率推断（ts02 §4.6 注）。

## 6. Hermes 侧集成约束（TS-07.6）

### 6.1 investment-runtime-policy skill 固化规则（冻结规范 §5.1）

Investment Profile 必须加载 `investment-runtime-policy` skill，固化以下规则（TS-07 补充 MCP 侧落地细节）：

| # | 规则 | MCP 侧落地 |
|---|---|---|
| 1 | 所有事实数据必须通过 MCP 获取 | Hermes 侧无任何 provider 客户端；无 DB 驱动依赖 |
| 2 | 禁止 terminal 直连数据库（psql/duckdb CLI/读写 data/） | 物理隔离兜底（§3.4 第 1 层） |
| 3 | 禁止依赖 Memory 保存事实（只存偏好与摘要） | 数值回答默认"现查 MCP"（规则 #6） |
| 4 | 禁止 LLM 心算关键指标（PE/DCF/收益/回撤等，冻结规范 §4.2） | 指标一律来自引擎工具（`get_market_metrics`/`run_valuation`/`get_portfolio_*`） |
| 5 | 投资结论必须引用 provenance | 消费包络 `provenance` 数组；无 provenance 的 decision-sensitive 结论禁止输出 |
| 6 | 数值类回答默认"现查 MCP"，禁止凭记忆作答 | 每次会话/每次 cron 运行都重新拉取 |
| 7 | Daily Brief / 深度研究按 Model Routing 选模型（§34） | `save_daily_brief.model_profile` 记录 profile 名（§6.3） |

**Freshness 纪律（§36.3 固化进 skill）**：消费 `get_daily_context` 或任何 decision-sensitive 工具返回值时，先检查 `freshness.overall`：

```text
OK      → 正常
WARNING → 允许生成判断，但必须显式标注数据异常
STALE   → 禁止 Buy/Hold/Sell 建议、Thesis 更新、Trade Proposal；
          允许异常报告 / 请求重同步（sync_* / get_job_status）/ 标记 Attention
FAILED  → 跳过 LLM 阶段（非交易日或同步失败）
```

### 6.2 cron 日报的 enabled_toolsets 限制（冻结规范 §31.1）

- 日报 cron（`daily-investment-brief`）的 `enabled_toolsets = web + mcp`（**不给 terminal/file**）——作为权限模型的运行时补充（§3.4 第 2 层）；
- Hermes Cron 只负责：获取 daily_context → 新闻研究（web）→ Thesis 分析 → Daily Brief 生成（冻结规范 §5.2）；**禁止全量同步、大规模计算**；
- 非交易日：daily_context 不存在或 `FAILED` → 跳过 LLM 阶段；**禁止在 Hermes 侧重复实现交易日历**（§31.1）——交易日判断只来自 Backend。

### 6.3 Model Routing（冻结规范 §34 落地）

```text
task_class → required_capability → model_profile    （配置层）
```

- **映射只存在于 Hermes 配置层**（cron job 的 model override / 会话配置），**禁止在业务逻辑中硬编码具体模型名**；
- **MCP 响应不携带具体模型名**：包络与工具输出中出现的模型相关字段只有 `engine_version`（引擎版本，非 LLM 模型）与 `save_daily_brief.model_profile`（profile 名）；
- `save_daily_brief` 输入必填 `model_profile`（`fast` / `deep` 等 profile 名），**禁止记录具体模型名**（§34：`daily_summary → fast`、`thesis_review → deep`）；
- 未来模型轮换不改变 MCP 契约：换模型只改配置映射，不改工具/包络/审计 schema。

### 6.4 会话与审计约定

- Hermes 每次会话开始时通过 `get_daily_context` 校验当日 freshness（若 context 存在）；
- 所有写操作（thesis revision、review、proposal、note、brief）的 `audit_events.actor_type='HERMES'`、`actor_id` 为 profile 标识、`request_id` 关联原始 MCP 请求（§1.3）；
- 会话结束不产生任何直接数据库写入；一切持久化经由 MCP 工具（或人工入口）。

## 7. 测试与验收（TS-07.7）

### 7.1 MCP 暴露面白名单（架构测试，冻结规范 §46 #5）

| 测试 | 断言 |
|---|---|
| 工具注册表 == 冻结契约 | `mcp/` 模块 `tools/list` 返回的工具集合与 §2 清单（28 个唯一工具）**逐名相等**；无清单外工具 |
| 禁止无约束工具 | 注册表中不存在 `raw_sql` 类、任意 SQL、表名参数类工具 |
| API/MCP 模块纯度 | `api/` 与 `mcp/` 模块不含业务计算逻辑（审计性检查，§46 #4） |
| provider 隔离 | `mcp/` 与 `api/` 禁止 import `providers.*`（ts05 §8.1） |
| 包络 schema 校验 | 每个工具响应通过统一包络 Pydantic schema（request_id/as_of/data/quality/provenance/freshness 字段矩阵，§1.4） |

### 7.2 权限矩阵测试（输入：§3.2 映射表）

- 每个工具 × 其权限级别：允许调用成功（happy path）；
- 每个工具 × 低于其级别的上下文：返回 `403 PERMISSION_DENIED`，且无副作用（无落库、无 job 创建）；
- `ACCOUNT_WRITE` 三工具：断言 MCP 注册表中**不存在**（调用 → 协议层 `-32601`）；
- `EXECUTION`：断言无任何 Broker/执行类工具；
- 越权尝试落 `audit_events`（action='PERMISSION_DENIED' + request_id）。

### 7.3 错误码测试（输入：§4.2 清单）

- 每个错误码至少一条触发路径（单元 + 集成）：
  - `DOMAIN_CONFLICT`：base_revision_id 过期 → 409（ts02 §12.3 并发测试）；
  - `MISSING_VALUATION_INPUT`：缺 wacc → 422 + `valuation_runs.status=BLOCKED_MISSING_INPUT`（ts01 §1.6）；
  - `STALE_INPUT_REJECTED`：决策敏感输入 STALE；
  - `INPUT_DATA_QUALITY_BLOCKED`：CONFLICT/REJECTED 输入；
  - `INVALID_INPUT`：wacc<=0、CN_ETF 传 run_valuation；
  - `TERMINAL_VALUE_UNDEFINED`：growth >= wacc；
  - `JOB_TRIGGERED`：超时转 job（mock 引擎延迟 >30s）；
- 错误消息安全：断言任何错误响应不含 SQL/表名/provider symbol（§4.5）。

### 7.4 freshness 门禁测试（输入：§1.5 / ts04 §7.5）

| 用例 | 断言 |
|---|---|
| `data_freshness=OK` | 三类写操作全部放行 |
| `=WARNING` | 写操作放行（§36.3 只禁非 OK？——**注意：§36.3 语义为 `!= OK` 即禁止**；TS-07 冻结：WARNING 也触发 `FRESHNESS_GATE`，与 ts06 §5.8.2/§2.2.3 一致，Hermes 侧 WARNING 允许带标注生成判断但 MCP 写门禁从严） |
| `=STALE` | `create_thesis_revision` / `record_thesis_review` / `update_thesis_assumption` / `create_trade_proposal` → `409 FRESHNESS_GATE` |
| `=FAILED` | 同上 + `get_daily_context` 返回 FAILED 语义（Hermes 跳过 LLM 阶段） |
| 恢复 | 重同步成功 → STALE→OK → 写操作恢复 |

> **WARNING 门禁裁决（TS-07）**：冻结规范 §36.3 字面为 `data_freshness != OK` 禁止三类写操作，即 WARNING 也在禁止之列。ts04 §7.5 表将 WARNING 的 Daily Brief 列为"允许（带标注）"，但写操作（Thesis/Proposal）按字面禁止。TS-07 统一为：**MCP 后端写门禁对 `overall != OK`（含 WARNING）一律拒绝**；Hermes 对话输出在 WARNING 下允许生成但必须标注。该从严裁决写入 §8 #5 供 ADR 复核。

### 7.5 PIT 测试（输入：§5）

- `get_thesis(as_of)` 黄金测试：历史 as_of → 断言返回版本 == 该时点 head（ts01 §1.6 验收）；
- `get_financial_history(as_of)` 重述场景：重述行在 as_of 前不可见、as_of 后可见（ts04 §5.4 #5）；
- `get_fundamentals` look-ahead 防护：`published_at > as_of` 的行不得返回；
- `get_portfolio(as_of)` 历史快照：`snapshot_date <= as_of` 取最近；
- QDII 四日期：`get_market_metrics` 输出同时含 market_date/nav_date/underlying_session_date/fx_as_of；对齐失败 → null + flag。

### 7.6 包络 / request_id / 审计联动测试

- 每个工具成功响应通过包络 schema；
- `request_id` 贯穿：一次 `create_thesis_revision` 调用 → `audit_events.request_id` 可关联到该请求的全部审计事件；
- 转 job 场景：`run_valuation` 的 `request_id` 出现在 `job_runs.params.request_id`，`get_job_status` 可追溯；
- 幂等测试：`sync_market_data` 同参数重复触发不创建新 job；`run_valuation` 同 request_id 重复提交返回同一 run。

### 7.7 验收清单（TS-07 冻结线）

| 验收问题 | 必须得到的答案 |
|---|---|
| Hermes 能否绕过 MCP 触达数据？ | 不能（物理隔离 + 白名单 + 权限矩阵三层） |
| 工具清单是否与冻结规范 §32 一致？ | 是（28 个唯一工具，架构测试逐名断言） |

## 8. 开放问题与下一步

### 8.1 开放问题（TS-07 未决，需 ADR / 实现期裁决）

1. **`create_thesis` vs `create_thesis_revision` 命名**：冻结规范 §32.6 登记 `create_thesis()`，ts01 §1.6 / 本报告登记 `create_thesis_revision()`。TS-07 以 `create_thesis_revision` 为准（真实语义是追加不可变 revision），`create_thesis` 作为"创建首个 revision"的兼容别名——需 ADR 回写冻结规范 §32.6，并在白名单测试中冻结最终清单。
2. **RESEARCH_WRITE 枚举扩展**：`create_thesis_revision`、`save_daily_brief` 归 RESEARCH_WRITE 是 TS-07 裁决，冻结规范 §33.1 未显式列举；需 ADR 回写。
3. **run_valuation 幂等语义精确化**：同参数不同 request_id 时"返回既有 run + flag" vs "409 IDEMPOTENCY_CONFLICT"二选一，TS-07 建议前者（与 sync 幂等一致），实现期冻结。
4. **sync 类工具权限归属**：归 READ（本报告裁决）vs 新增独立级别（如 `JOB_TRIGGER`）——v0.1 建议 READ，避免权限级别爆炸；跨机部署引入用户级身份后复核。
5. **WARNING 门禁从严**：`overall != OK`（含 WARNING）即拒绝写操作（§7.4 裁决），与冻结规范 §36.3 字面一致；若产品希望 WARNING 下放行 Thesis 更新（带标注），需 ADR 修改 §36.3。
6. **search_research 检索后端**：关键词 vs 向量检索由 M4 Research Memory 决定；工具契约已冻结，实现不影响契约。
7. **`get_daily_context` 双登记**：§32.7/§32.8 重复登记已裁决为单一工具；白名单测试按 28 个唯一工具断言，避免计数歧义。
8. **未来跨机认证**：API Token / Authentication Layer / Request Audit 的引入时机与方案（§1.2），需在跨机部署 ADR 中细化；权限矩阵不变。
9. **分页与限流**：列表上限（200）与 MCP 调用频率限制（v0.1 个人单机暂不冻结，跨机/多用户后必须引入）。
10. **原始文档（财报 PDF）下载通道**：不在 MCP 暴露面；`get_latest_filings` 只给元数据，文档下载通道由 M1 Raw Evidence Store 确定（§2.2.3）。
