# Hermes Investment Office 本地使用手册

## 1. 启动与打开

确认 Docker Desktop 已运行，然后执行：

```bash
cd hermes-investment-office
./scripts/hermes start
./scripts/hermes open
```

- Dashboard：<http://127.0.0.1:8501>
- Backend 健康检查：<http://127.0.0.1:8000/healthz>
Backend API 文档：<http://127.0.0.1:8000/docs>

`start` 会幂等执行迁移、创建默认观察池和手工 REAL 组合，不会覆盖已有账本，也不会写入示例行情。

左侧一级导航固定为“今日、标的、组合、问 Hermes”。ADR-011 已取代历史的“今日、观察池、持仓、回顾、问 Hermes”五入口结构；“观察池”现在只是“标的”页的范围筛选，“回顾”由标的事件、局部历史模式与 Hermes 历史会话承载。

### 统一写入确认规则

任何会改变持久状态的操作都遵循“填写或选择 → 预览 → 独立确认”。预览层会展示对象、数值、日期和影响；点击“取消”不会调用 Backend 写接口。该规则覆盖标的加入/移出、主观估值、Hermes 研究结论落库、期初迁入、现金与交易流水、流水更正、建议批准/拒绝及外部实际成交登记。

## 2. 问 Hermes

在左侧选择“问 Hermes”，即可在 Dashboard 内直接对话。可研究：

- 当前手工持仓；
- 观察池标的；
- 尚未录入系统的其他股票或 ETF。

系统内标的由 Hermes 通过 `hermes-investment-office` MCP 查询 Backend 事实、时点、质量和来源。系统外标的会使用公开网络来源，并在回答中区分外部事实与 Backend 事实；缺少确定性估值、收益或风险结果时必须明确说明。

页面会把 Hermes 的持久会话编号保留在本机 URL 中。刷新页面后会恢复对话；点击“新建会话”只开始一段新对话，不删除旧会话。

展开“历史会话”可以管理过去的研究：

1. 选择一段会话后点击“打开此会话”，继续原来的上下文；
2. 点击“生成导出文件”，再点击“下载 Markdown”，将用户与 Hermes 的可见对话保存到本机；
3. 点击“删除会话”后还要再次点击“永久删除”。删除会同时移除该会话的全部消息，无法撤销。

历史列表只显示由 Investment Office 创建的对话，不混入 Hermes CLI、自动任务或子 Agent 会话。会话正文仍由 Hermes 保存在 `~/.hermes/state.db`，Dashboard 不直接访问该数据库。

Hermes 只能研究、解释和提出建议。它不能连接券商、下单、审批建议、登记实际成交或修改 REAL 账本。

若页面显示“对话服务未连接”，运行：

```bash
./scripts/hermes status
./scripts/hermes restart
./scripts/hermes logs chat
```

## 3. 添加和研究标的

进入“标的”，展开页面顶部的“添加或管理标的”。只需填写六位证券代码和股票/ETF 名称，然后点击“加入并初始化”；页面先显示标的预览，只有再次点击“确认加入并初始化”才会写入。

系统会自动完成代码标准化、沪深市场判断、A 股/ETF 类型判断、交易所和 Provider Symbol 映射，并立即执行以下初始化：

1. 行情与真实日 K；
2. 股票财务事实，或 ETF 净值与指标；
3. 财报披露索引、分红和公司行动；
4. 明确标注“待研究”的基础观点档案。

初始化完成后会直接打开该标的详情，并显示各阶段的完成、暂无数据或失败状态。也可输入 `600519.SH` 或 `003816.SZ`；若标的已登记，系统会复用原记录并重试缺失资料，不会重复创建。

若外部数据源当时不可用，标的仍会留在观察池中。恢复后在详情页点击“补齐资料”即可重试。当前自动识别范围为沪深 A 股与场内 ETF；跨境 ETF 会根据名称中的 `QDII`、跨境、纳指/纳斯达克、标普、道琼斯、恒生、日经、德国或法国等关键词建立待核实的跟踪指数档案。

“观察池”和“全部标的”是同一页面内的筛选，不是两个独立入口。选择标的后可以查看：

- “行情”：不复权真实日 K，以及 MA5、MA20、MA30；
- “估值”或“ETF 指标”：股票显示 Backend 客观估值，ETF 显示净值、溢折价和指数指标；
- “研究”：基础观点和用户明确确认写入的 Hermes 研究；
- “事件”：财报披露、公司行动、笔记、证据与观点复核；
- “来源”：Provider、数据时点、质量与 provenance。

桌面观察池显示“代码、名称、最新价、日涨跌、跟踪指数、行情日”六列。窄屏固定保留“代码、名称、最新价、日涨跌”四个核心列，不用缩小文字强塞额外字段；跟踪指数与行情日可在下方标的详情查看。行情图是不复权日 K，MA5/MA20/MA30 分别使用蓝、琥珀与紫色；涨跌遵循 A 股红涨绿跌。

股票的主观价值区间不会自动生成。先点击“问 Hermes 形成假设”，再在估值区录入悲观、基准、乐观价值和概率；预览无误后点击“确认并运行估值”。

## 4. 第一次建账

进入“组合 → 手工记账”：

1. “迁入现有持仓”：逐只填写标的、当前数量、平均成本和起始持有日。系统会写入一组配对期初流水，建立数量和成本，但不会改变当前现金。
2. “现金变动”：录入当前可用现金。若已有现金为 50,000 元，登记一笔 `CASH_IN 50000`。
3. 返回“当前持仓”核对数量、平均成本、最新价、市值和未实现盈亏。

没有券商账户同步。页面显示的所有真实持仓和现金都来自上述本地手工账本。

## 5. 日常记账

- 买入：填写实际日期、标的、数量、成交价和费用。
- 卖出：只能卖出该日期账本中已有的数量；超卖会被拒绝。
- 分红：填写标的、到账日期和金额。
- 费用：填写标的、发生日期和金额。
- 现金转入/转出：使用“现金变动”，金额方向由页面自动处理。

买卖金额由数量乘以成交价确定，费用单独记入现金流和成本/已实现盈亏。系统拒绝零金额、金额不一致和超卖。

流水写错时使用“流水更正”。系统追加一条 `REVERSAL` 抵消原流水，不修改或删除历史。

## 6. 交易建议

Hermes 可以创建 `PROPOSED` 建议，但建议不是订单：

1. 用户在 Dashboard 批准或拒绝建议。
2. 批准不会触发任何交易。
3. 若用户已在系统外完成交易，再填写实际成交日期、价格、数量和费用。
4. 只有第 3 步完成后，本地账本才新增手工交易流水。

系统没有券商 API、券商账户、自动下单、资金划转或自动成交能力。

## 7. 数据与新鲜度

Backend 在工作日 `07:30`（`Asia/Shanghai`）刷新观察池行情、股票财务事实、ETF/QDII 数据、公司行动、组合快照、风险和每日上下文。需要立即刷新时：

```bash
./scripts/hermes refresh
```

外部代理由用户自行管理，并通过本机 `backend/.env` 的 `HERMES_EXTERNAL_PROXY` 提供。系统只使用该地址，不会管理代理进程。网络或代理不可用时：

- 同步 Job 记录明确错误；
- 首页新鲜度显示 `WARNING`、`STALE` 或 `FAILED`；
- Hermes 停止决策敏感写入；
- 系统不会用示例数据填补缺口。

结构化数据源按数据域分工：

- TuShare：A 股/场内 ETF 行情、复权、财务、基金 NAV 与 A 股指数数据主链路；
- AkShare 新浪源：A 股行情 fallback 和交易日历；
- AkShare 东方财富源：ETF 行情/NAV、基金持仓与 QDII 额度状态；
- AkShare 同花顺源：财务摘要 fallback；
- Yahoo Finance：美国指数与 USD/CNY 日频数据；
- FRED：宏观序列与汇率交叉验证；
- 乐咕乐股：A 股指数 PE/PB 历史。

交易日历从新浪同步到本地持久表，并可人工校准。标的详情“来源”页按数据域列出 Provider、`provenance_id`、数据时点/报告期与质量状态；若没有真实来源记录，页面明确显示空状态。Provider fallback、过期和失败都会留在 freshness、quality 与 provenance 中，不会静默替换。

## 8. 历史模式与长期研究写入

系统默认始终显示最新数据，不再使用一个全局日期控制所有页面。

- 在“标的”详情展开“查看历史版本”，可按指定日期查看当时可见的行情、财务、观点和事件；历史模式严格只读。
- 在“组合”展开“查看组合历史快照”，可查看当日以前的账本、持仓与建议；历史模式不能记账、审批或登记成交。
- Hermes 对话会自动保存，但不会自动改动长期研究状态。助手回答下方的“研究笔记、纳入投资观点、建立估值、跟踪事项”都需要选择标的、预览并再次确认。

## 9. Hermes 自动任务

```bash
hermes gateway status
hermes cron list
hermes mcp test hermes-investment-office
```

已配置任务：

- 工作日 `09:00`：每日简报；
- 周六 `10:00`：周度组合回顾；
- 1、4、7、10 月 1 日 `10:00`：季度投资回顾。

所有任务使用本机 MCP 白名单。数据新鲜度非 `OK` 时只报告缺口，不生成投资动作；REAL 流水、建议审批和实际成交登记始终由用户完成。

## 10. 备份

LaunchAgent `com.hermes.investment-office.backup` 每天 `03:00` 执行：

- PostgreSQL 自定义格式备份；
- Hermes 数据卷压缩包；
- 30 份每日备份；
- 12 份周六备份。

默认位置为 `~/hermes-backups`。手工备份：

```bash
./scripts/hermes backup
```

恢复会覆盖现有数据库，只在明确选择备份文件并阅读交互确认后执行：

```bash
./scripts/backup.sh --restore-db /绝对路径/hermes_YYYYMMDD_HHMMSS.dump
```

## 11. 故障排查

```bash
./scripts/hermes status
./scripts/hermes logs backend
./scripts/hermes logs dashboard
./scripts/hermes logs chat
hermes gateway status
```

- Dashboard 无法打开：确认 `hermes-dashboard` 为 healthy，并检查 Dashboard 日志。
- Backend 报错：检查 `hermes-backend`、`hermes-db` 和 `/healthz`。
- 数据过期：先确认外部代理，再运行 `./scripts/hermes refresh`，最后查看“今日”的运行状态。
- 新标的部分资料为空：进入“标的”详情查看“资料初始化”，修复对应 Provider 后点击“补齐资料”。
- Hermes 定时任务不触发：`hermes gateway restart` 后再次运行 `hermes gateway status`，心跳应为约 60 秒内。
- “问 Hermes”无法连接：确认 `./scripts/hermes status` 显示“对话服务：已就绪”，再查看 `./scripts/hermes logs chat`；系统不会静默切换到其他模型。

停止服务使用 `./scripts/hermes stop`。它不会删除数据库卷或数据卷。
