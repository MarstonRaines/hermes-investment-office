# Hermes Investment Office Technical Specification：Hermes Integration Design 研究报告

## 执行摘要

本报告将 **TS-09 Hermes Integration Design** 定义为控制平面（Hermes）与事实/计算平面（Investment Backend）的完整集成设计。前提是 [ADR-008（Hermes 身份澄清）](ADR/ADR-008-hermes-identity.md)：**Hermes 角色 = Nous Research 的 Hermes Agent 产品**（MIT，`~/.hermes`，DeepSeek 模型）。

TS-01~TS-08 冻结了 Backend 的一切（40+ 张表、六类 Provider、六大引擎、28 个 MCP 工具、18 错误码、Freshness 门禁）。TS-09 负责回答最后一个问题：

> **Hermes Agent 如何成为投资经理？** —— 用什么 skills、跑什么 cron、怎么调用 MCP、怎么约束自己。

TS-09 最重要的设计结论：

> **Hermes Agent 是大脑，但它的"记忆"受限于 §4.1——所有投资事实必须现查 MCP；Backend 的 28 个 MCP 工具是它唯一的投资数据窗口；8 个业务 skill 是它的方法论；3 个 cron 任务是它的例行工作；Freshness 门禁是它的行为刹车。**

载体能力已本机实测（ADR-008 §7），与冻结规范 §31/§33/§34 **零冲突**：

| 冻结要求 | 载体能力（实测） |
|---|---|
| §31.1 MCP HTTP → 127.0.0.1:8000/mcp | `hermes mcp add investment-backend --url http://127.0.0.1:8000/mcp` |
| §31.1 标准 5-field cron | `hermes cron create '0 9 * * *' <prompt>` + monitor 模式 + --deliver + --model |
| §34 模型路由 | `hermes model` 默认档 + cron 任务级 `--model` 覆盖 |
| §31 skills | SKILL.md（agentskills.io 标准）|

## 1. 载体与部署拓扑（TS-09.1）

### 1.1 进程拓扑（v0.1 单机）

```text

│  Mac（127.0.0.1）                                     │
│                                                     │
│  Hermes Agent（大脑）                                 │
│  ├── hermes gateway（用户服务，多平台入口）              │
│  ├── hermes cron（调度器：日报/周报/季报）               │
│  ├── hermes mcp client ──→ investment-backend         │
│  └── skills/（投资方法论）                             │
│            │                                         │
│            ▼                                         │
│  Investment Backend（事实与计算平面）                   │
│  FastAPI :8000（MCP /v1/mcp + REST /v1）              │
│            │                                         │
│            ▼                                         │
│  PostgreSQL（容器内部网络，物理隔离 §4.4）              │

```

### 1.2 安装与注册（M5 施工步骤）

```bash
# 1) MCP server 注册（§31.1 端点）
hermes mcp add investment-backend \
  --url http://127.0.0.1:8000/mcp \
  --connect-timeout 15
hermes mcp list                        # 验证工具注册为 mcp__investment_backend__*

# 2) Gateway 用户服务（多平台入口，ADR-004 远程基础）
hermes gateway install                 # 装为后台用户服务
hermes gateway status                  # 确认 running

# 3) Skills 安装（项目 skills/ → 载体）
# 项目仓库 skills/ 目录（冻结规范 §43）经 symlink/复制安装：
ln -s /path/to/project/skills ~/.hermes/skills/investment
hermes skills list                     # 验证 10 个 skill 可见

# 4) 默认模型确认
hermes model                           # deepseek-v4-flash（已配置）
```

### 1.3 工具命名与暴露面（冻结）

- 注册后模型侧工具名为 `mcp__investment_backend__<tool>`（如 `mcp__investment_backend__get_portfolio`）；
- **TS-07 的 28 个唯一工具 = 模型可见工具全集**（白名单）；`hermes mcp configure investment-backend` 可做工具级开关（§33.2 等效机制之一）；
- Backend 侧 MCP 权限分级（READ/RESEARCH_WRITE/PROPOSAL_WRITE）照常生效——工具白名单只是第一层，权限裁决在 Backend。

## 2. Investment Profile 落地（TS-09.2）

### 2.1 Profile 组成（冻结规范 §31 映射）

| §31 要求 | 载体落地 |
|---|---|
| Skills: investment-runtime-policy | `~/.hermes/skills/investment/investment-runtime-policy/SKILL.md`（**强制常驻**，见 §4.1）|
| Skills: investment-policy | `~/.hermes/skills/investment/investment-policy/SKILL.md` |
| Skills: AI Berkshire adapted | `skills/vendor/ai-berkshire/*`（适配后入册）|
| Skills: LangAlpha-derived | `skills/vendor/langalpha/*`（裁剪后入册）|
| Skills: custom research | 8 个业务 skill（§3）|
| MCP: investment-backend | `hermes mcp add`（§1.2）|
| Cron: daily-investment-brief | `hermes cron create`（§5.1）|
| Cron: weekly-portfolio-review | `hermes cron create`（§5.2）|
| Cron: quarterly-thesis-review | `hermes cron create`（§5.3）|

### 2.2 常驻规则加载（runtime-policy 强制）

- `investment-runtime-policy` skill 内容为**行为红线**（§4.1），必须保证每个会话/任务可见：
  - cron 任务的 `--skill investment-runtime-policy` 显式附加；
  - 交互会话由 `SOUL.md` 或 persona 层引用（载体启动时加载）；
- **架构测试**：cron 任务清单断言——三个投资任务均带 `--skill investment-runtime-policy`。

### 2.3 配置隔离

- 投资 Profile 与开发 Profile（web/headless）分离：投资任务用独立 cron 命名空间（`investment-*` 前缀）、独立 skills 目录；**不得与其他开发项目的 skills 混用**（冻结规范 §31）；
- Backend token（未来认证激活）走 `hermes secrets`（外部 secret 源）或环境变量，不进 skill 文本。

## 3. Skills 体系（TS-09.3）

### 3.1 目录与安装

```text
项目仓库 skills/（冻结规范 §43，随 git 版本管理）
├── investment-runtime-policy/    # 行为红线（§4.1）
├── investment-policy/            # 用户投资政策
├── daily-brief/                  # 日报生成
├── stock-research/               # 个股研究
├── etf-analysis/                 # ETF 分析（含 QDII）
├── valuation-analysis/           # 估值分析
├── portfolio-review/             # 组合回顾
├── thesis-review/                # Thesis 复核
└── vendor/
    ├── ai-berkshire/             # 适配来源（§3.3）
    └── langalpha/                # 适配来源（§3.3）
```

安装：项目 `skills/` → `~/.hermes/skills/investment/`（symlink，随仓库更新）；`hermes skills audit` 周期性校验。

### 3.2 业务 skill 契约（每个 SKILL.md 的结构，Anthropic 规范）

```markdown
---
name: <skill-name>
description: <一句话：何时用、输出什么>
---

# <技能名>

## 输入（from MCP）
- 必须现查的 MCP 工具与参数（禁止凭记忆）

## 工作流
1. <步骤>（每一步标注调用的 MCP 工具）
2. ...

## 输出 Artifact
- <结构化产出>（落库工具：save_research_note / create_thesis_revision / save_daily_brief）

## Human Review 点
- <需要用户确认的决策点>

## 红线
- <本 skill 特有的禁止项（如：不估算、不静默 fallback、freshness 门禁）>
```

### 3.2.1 八个业务 skill 一览

| Skill | 触发场景 | 核心 MCP 工具 | 产出 |
|---|---|---|---|
| **daily-brief** | 每日 cron（§5.1）| get_daily_context →（新闻研究）→ save_daily_brief | 日报（存 Backend）|
| **stock-research** | 用户要求研究个股/观察池标的 | get_fundamentals / get_financial_history / get_latest_filings / get_evidence / save_research_note | 研究笔记 + 可选 Thesis 草案 |
| **etf-analysis** | ETF/QDII 分析 | get_etf_metrics / get_market_snapshot / get_price_history | 折溢价/FX/估值带分析 |
| **valuation-analysis** | 估值请求 | run_valuation / get_latest_valuation / get_valuation_history | 估值解读（假设→结果→解释）|
| **portfolio-review** | 每周 cron + 用户请求 | get_portfolio / get_positions / get_portfolio_exposure / get_portfolio_risk | 组合周报 |
| **thesis-review** | 季度 cron + 事件触发 | get_thesis / record_thesis_review / update_thesis_assumption | 复核结论 + 假设状态更新 |
| **investment-policy** | 常驻（所有决策参考）| —（政策文本）| 决策约束（范围/周期/纪律）|
| **investment-runtime-policy** | 常驻（行为红线）| —（规则文本）| 行为约束（§4.1）|

### 3.3 来源适配（AI Berkshire / LangAlpha / Anthropic）

| 来源 | 适配规则 | 入册清单 |
|---|---|---|
| AI Berkshire（方法论层）| 审核 → 挑选 → vendor → 适配（冻结规范 §29：不复制其 Tool Runtime）| investment-checklist / investment-research / financial-data / earnings-review / portfolio-review / thesis-tracker / thesis-drift / news-pulse |
| LangAlpha（工作流概念）| 借 Skill 思路/Tool Contract/Prompt（§30），Sandbox/DB 依赖重写为 MCP 调用 | DCF / Comparable Companies / Three Statement Model / Model Audit / Morning Note / Sector Overview / Competitive Analysis |
| Anthropic financial-services | SKILL.md 结构规范采用（SKILL.md → Workflow → Artifact → Human Review）| earnings-reviewer / market-researcher 的**结构模板**（vendor/adapt）|

**适配纪律（冻结）**：
1. 直接复制 SKILL.md 通常不可用——必须审核适配后 vendor（§29/§30）；
2. 所有 vendor skill 的数据获取**一律改走 MCP**（禁止保留原项目的直连数据逻辑）；
3. 每个 vendor skill 记录来源与许可证（个人自用场景下 AGPL/EPL 可复用，ADR-008 许可证决策）。

## 4. 会话纪律与权限（TS-09.4）

### 4.1 investment-runtime-policy（行为红线，冻结）

每个会话/任务加载。核心规则（冻结规范 §5.1 七条 + 补充）：

```text
1. 所有事实数据必须通过 MCP 获取（mcp__investment_backend__*），禁止凭记忆作答
2. 禁止 terminal 直连数据库（psql/duckdb CLI/直接读写 data/ 文件）
3. 禁止依赖 Memory 保存事实（Memory 只存偏好与摘要，§4.1）
4. 禁止 LLM 心算关键指标（PE/收益率/回撤等——数字必须来自引擎）
5. 投资结论必须引用 provenance（quality 与来源随数字给出）
6. 数值类回答默认"现查 MCP"，禁止凭记忆作答
7. Daily Brief / 深度研究按 Model Routing 选模型（§6）
8. （补充）Freshness 门禁：daily_context.data_freshness != OK 时禁止
   生成 Buy/Hold/Sell 建议、更新 Thesis、创建 Trade Proposal（§36.3）
9. （补充）ACCOUNT_WRITE 不存在：Hermes 永远不写真实交易（§25.2/§33.1）
10. （补充）工具白名单：只用 MCP 28 工具；禁止 raw_sql 类（Backend 无此工具，双保险）
```

### 4.2 Freshness 门禁行为（标准话术）

`data_freshness != OK` 时的标准动作（冻结规范 §36.3）：

```text
禁止：买卖建议 / Thesis 更新 / Trade Proposal
允许：输出数据异常报告 / 请求重新同步（get_job_status + sync 触发）/ 标记 Attention

标准话术模板：
  "当前数据新鲜度为 {status}（{原因}），按系统纪律我不能基于过期数据给出
   投资建议。已为你标记 Attention Item；需要我先触发数据重新同步吗？"
```

### 4.3 工具白名单（§33.2 等效机制）

| 层 | 机制 | 说明 |
|---|---|---|
| L1 | Backend MCP 权限分级 | READ/RESEARCH_WRITE/PROPOSAL_WRITE（TS-07 §3）|
| L2 | `hermes mcp configure investment-backend` | 工具级开关（可对交互会话收紧）|
| L3 | cron 任务 `--skill` 约束 | 日报任务只附加 daily-brief + runtime-policy（等效 enabled_toolsets=web+mcp 语义）|
| L4 | runtime-policy 纪律 | 最后一道行为约束 |

> v0.1 建议：交互会话 L1 全开（READ 全工具 + 写工具按权限）；cron 日报任务 L3 收紧（不带研究/写类 skill）。

### 4.4 记忆边界（§4.1 落地）

| 可入记忆 | 禁止入记忆（必须现查）|
|---|---|
| 用户长期投资偏好、研究偏好 | 当前仓位/成本/市值/现金/收益率 |
| 公司长期逻辑摘要（非数值）| PE/PB/财务指标/当前价格/估值结果 |
| 历史讨论上下文 | 目标仓位/风险/公告状态/交易流水 |
| Thesis 摘要（版本/状态，非假设数值细节）| 任何决策敏感数值 |

## 5. Hermes Cron 三任务（TS-09.5）

### 5.0 调度边界（冻结规范 §5.2/§35.1 重申）

- Hermes Cron **只负责**：获取 daily_context、新闻研究、Thesis 分析、日报生成；
- 数据同步/计算引擎由 **Backend Scheduler** 自主运行（Hermes 不触发全量同步，不等待计算）；
- 非交易日：daily_context 不存在或 FAILED → **跳过 LLM 阶段**（禁止在 Hermes 侧实现交易日历，§31.1——判断依据是 daily_context 本身）。

### 5.1 daily-investment-brief（每日日报）

```bash
hermes cron create '0 9 * * 1-5' \
  --name investment-daily-brief \
  --deliver local \
  --skill investment-runtime-policy \
  --skill daily-brief \
  --model deepseek-v4-flash \
  "执行 daily-brief skill：获取 daily_context 并校验 freshness；
   若 OK 则分析 Attention Items（仅这些），生成日报并 save_daily_brief；
   若非 OK 按 §4.2 标准话术处理。"
```

设计要点：

| 项 | 决策 |
|---|---|
| 调度 | `0 9 * * 1-5`（工作日 9:00；**交易日判断不在此层**——非交易日 daily_context 缺失即跳过）|
| 触发方式 | 方案 A：固定 cron；方案 B（增强）：**monitor 模式**——`--monitor-script` 检查 daily_context 是否更新，**未更新不触发 agent**（省 token，推荐 M6 后启用）|
| 新闻研究 | 3 分钟硬中断内完成（§12.4）；超时则将 news collection 下沉 Backend Job（ADR 记录）|
| 分析范围 | **只分析 Attention Items**（§38），禁止全量分析 |
| 模型 | fast 档（daily_summary，§34.2）|
| 交付 | v0.1 `--deliver local`（存 Backend + Dashboard 展示，§39）；Telegram 等作为后续增强（ADR）|

### 5.2 weekly-portfolio-review（每周组合回顾）

```bash
hermes cron create '0 10 * * 6' \
  --name investment-weekly-review \
  --deliver local \
  --skill investment-runtime-policy \
  --skill portfolio-review \
  "执行 portfolio-review skill：组合状态/风险/暴露/与目标配置偏差，
   输出周报并 save_research_note（或独立周报对象，M6 细化）。"
```

### 5.3 quarterly-thesis-review（季度 Thesis 复核）

```bash
hermes cron create '0 10 1 1,4,7,10 *' \
  --name investment-quarterly-thesis \
  --deliver local \
  --skill investment-runtime-policy \
  --skill thesis-review \
  --model deepseek-v4-flash \
  "执行 thesis-review skill：遍历 ACTIVE/UNDER_REVIEW thesis，
   逐假设核对 test_condition 与最新证据，输出复核结论
   （REAFFIRM/REVISE/INVALIDATE 建议，最终确认权在用户）。"
```

设计要点：deep 档模型（thesis_review，§34.2）；**健康状态切换需用户确认**（§1.3 原则：health 判定保存 reason/evidence/actor，禁止无来源切换）。

### 5.4 cron 任务验收（架构测试挂钩）

- 三个投资任务存在且前缀 `investment-`；
- 每个任务均带 `--skill investment-runtime-policy`；
- daily-brief 任务不带研究/写类 skill（等效工具集限制）；
- 任务 prompt 不含具体模型名之外的业务硬编码（模型名在配置层，允许）。

## 6. Model Routing 落地（TS-09.6）

### 6.1 分档（冻结规范 §34 落地）

| task_class | capability | model_profile | 载体配置 |
|---|---|---|---|
| daily_summary | fast_reasoning | fast | cron 任务 `--model deepseek-v4-flash`（或未来 fast 档）|
| research | standard_reasoning | standard | 交互会话默认（`hermes model` 默认）|
| thesis_review | deep_reasoning | deep | quarterly cron `--model <deep>`（pi-ai 或未来档）|

### 6.2 规则

- task_class → model_profile 映射**只在 cron 任务配置层**（`--model` 参数），不进业务逻辑（§34）；
- `hermes fallback` 配置备用 provider（主模型故障时降级）；
- 交互会话中用户显式指定模型时尊重用户选择（会话级覆盖）。

## 7. 工作流编排（TS-09.7，skill ↔ MCP ↔ artifact）

### 7.1 研究工作流（stock-research / etf-analysis）

```text
用户："研究一下 510300"
  │
  ▼
Hermes（stock-research skill）
  ① resolve_instrument("510300") → instrument_id      [MCP]
  ② get_fundamentals + get_financial_history          [MCP]
  ③ get_latest_filings → 公告解读                      [MCP]
  ④ get_evidence / search_research（历史研究）          [MCP]
  ⑤ 分析 → save_research_note（provenance 随附）       [MCP·RESEARCH_WRITE]
  ⑥ 若用户要求 → 起草 Thesis（create_thesis_revision 草案，用户确认后落库）
```

边界：研究产出（笔记）可自动落库；**Thesis 创建/更新需用户确认**（Business Owner = Investor）。

### 7.2 估值工作流（valuation-analysis）

```text
用户："按 WACC 9%、永续增长 2.5% 给茅台估值"
  │
  ▼
Hermes（valuation-analysis skill）
  ① get_fundamentals（财务事实）                      [MCP]
  ② run_valuation(instrument, DCF, assumptions)       [MCP]  ← Hermes 只提假设
  ③ 引擎校验假设（缺失 → MISSING_VALUATION_INPUT 回显缺什么）
  ④ 解释结果（bear/base/bull + margin_of_safety + provenance）
  ⑤ 绝不自动补假设（无默认参数范式，ts06 E1）
```

### 7.3 Thesis 复核工作流（thesis-review）

```text
触发：季度 cron / 事件驱动（财报发布、红线触发）
  │
  ▼
Hermes
  ① get_thesis(as_of, include_evidence/reviews)       [MCP]
  ② 逐假设核对：get_fundamentals + get_latest_filings 找最新证据 [MCP]
  ③ 提议状态迁移（update_thesis_assumption）→ 等待用户确认 [MCP·RESEARCH_WRITE]
  ④ 用户确认后 record_thesis_review                   [MCP·RESEARCH_WRITE]
  ⑤ 若结论 REVISE → 基于 base_revision 创建新版本（409 DOMAIN_CONFLICT 防护）
```

### 7.4 观察池管理（ADR-006）

```text
用户："把海天味业加入观察池"
  │
  ▼
Hermes
  ① resolve_instrument("海天味业")                    [MCP]
  ② add_watchlist_member                              [MCP·RESEARCH_WRITE]
  ③ 提示：加入后即进入每日同步/研究范围（ADR-006 D2）
  ④ 可选：立即触发一次按需同步（sync_market_data 幂等触发）
```

### 7.5 组合建议工作流（proposal 边界）

```text
Hermes 任何"建议买入/卖出"场景：
  ① 数据全部现查 MCP（get_portfolio/get_positions/get_latest_valuation...）
  ② 提议 create_trade_proposal（PROPOSAL_WRITE，REAL 最高权限）
  ③ 明确告知：需要用户在 Dashboard/CLI 人工确认后由 Backend 落账
  ④ 永不、永不允许写真实交易（ACCOUNT_WRITE 只属于人工入口）
```

### 7.6 工作流纪律

| 纪律 | 说明 |
|---|---|
| 每个工作流步骤标注 MCP 工具 | skill 文本内强制（SKILL.md 模板"输入"节）|
| Artifact 落库优先 | 研究产出落 research_notes；结论落 thesis_revisions；日报落 daily_briefs |
| 不跨模块代写 | Hermes 不直接操作数据库（物理隔离 + 无 SQL 工具）|
| 409 冲突即停 | base_revision 过期 → 停止并提示用户基于最新版本重来 |
